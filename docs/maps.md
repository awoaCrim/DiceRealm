# 地图图册与生图

地图是独立资源，每张图保存自己的用途、比例数值和比例依据。Unity 玩家端显示权威当前场景选中的已发布玩家图；切图同时切换尺度与该图的单位位置。新冒险中，AI可在探索需要时请求当前公开地点的示意图，需要精确战斗空间时优先选用已有局部图；缺图再沿现有生成流程补充。**自动显示不等于自动生图**：进入地点、启用剧本、打开图册和普通GET仍不触发生图。手工制作与纠错保留为高级入口。

---

### 逐图尺度与局部战术图（工具契约42）

`purpose` 为 `region/settlement/tactical/schematic`，表示区域、城镇、局部战术或示意用途；`kind` 仍是图册分类。两者都不决定距离。每张图的 `grid.cellPixels` 与 `grid.distance/units` 分别表示像素跨度和对应真实长度，`grid.scaleBasis:{kind,detail}` 记录 `source` 原资料标注、`dm` 本场采用或 `unknown` 尚未确定。依据说明可公开；旧图缺字段显示“比例依据未记录”，不自动补成原版资料。

有原始网格时记录图注距离并对齐格宽与偏移。没有网格但有比例尺时，在工作台选择两点并输入实际长度；例如200像素对应20尺，就是每像素0.1尺。`type=none` 仍可保留这一比例。没有可靠依据则保持 `uncalibrated=true`、依据 `unknown`，不输出精确距离。仅看出格数、建筑或树木的大小不能确定真实长度。

v42 的 `map_request(kind,purpose,tacticalScale?)` 仍只使用当前公开地点资料；局部图可给 `tacticalScale:{longEdgeFeet}` 明确本场采用范围，省略时采用120尺。它是主持设计的局部空间，生成完成后按实际成品宽高保存 `dm` 比例，不冒称原图测绘。已有城镇图不阻止补局部图；按场景与用途复用同一请求槽，优先复用已校准且适合的小型局部图，失败/撤下不自动重新生成。风格参考只借外观，不复制比例。

`map_state_read` 和每个新模型帧包含当前图及可选公开地图的实际用途、尺度、依据、版本和图片身份。`map_select(mapId,mapVersion)` 明确选择当前场景的已发布玩家图；下一模型帧冻结选中的真实图片，不能用城镇截图来操作另一张局部图。选择本身不移动单位。

新版 `encounter_prepare` 不再接收独立像素格宽。适用局部图若为100像素／10尺，棋盘叠加50像素／5尺逻辑网格，原图100像素仍为10尺。图册保存原尺度，棋盘与AI采用等物理比例的细格。区域/城镇、未知尺度或缺少空间细节的图不能靠修改distance变成战术图；需选用或补充局部图。活动战斗继续锁定原图及版本，既有旧战斗按其已冻结标尺恢复。

同一单位跨图继续使用原实体ID和机械状态，各图只保存明确给定的位置；城镇定位标记与局部站位分别保留，不自动换算归一化坐标，也不回血或复制角色。区域/城镇头像是易点击的定位标记，随地图放大或缩小。战术图按已记录体型及实际比例表达占地；视觉缩小时仍保留最小点击范围，密集时只避让屏幕头像并保留实际位置锚点，不移动角色。直接点头像查看或选目标，不再显示右上角常驻“单位”菜单；只有头像挤不下时才出现临时选择入口。

### 没有地图的剧本遭遇：空白方格

剧本给当前场景写了可开的遭遇（`ContentRuntime.AvailableEncounter`），场景却没有已发布的玩家地图、服务端也不能生图时，在此场景开始的第一条行动（`ValidateHarnessStart`）自动安装一张空白方格：12×8 格、每格 64 像素 / 5 尺，`purpose=tactical`、比例依据 `source`，绑定当前场景并发布。它是普通的玩家地图，AI 主持照常读棋盘、摆放队员与敌人、委派战斗；主持可以换图或撤下，撤下后不会被下一条行动放回，因为建图、导入、绑场景和发布各用由战役与场景决定的固定请求编号，只会重放。能生图时不安装，仍由 AI 主持按需请求局部战术图；没有剧本遭遇的场景也不安装。安装失败只记日志，行动照常进行、主持看到的仍是无图。来源是 2026-11-22 网页真实模型实测：无图时 AI 主持只能把交锋交给真人裁定。回归入口 `BlankGridTests`。

<a id="ai-按需地图工具契约13"></a>

### 旧 AI 按需地图（工具契约13—41）

`map_request(kind)`仅接受 `world/region/settlement/dungeon/battle`。必须是已批准玩家的已授权新冒险，先读取当前公开情境；模型不能指定任意prompt、地点或参考图。服务端从当前公开场景与本地点已公开记忆构造有界示意图描述，不发送主持秘密、未到达知识、角色经历或私有行动原文。地图关联当前地点，图片就绪自动发布玩家版。

同一地点只创建一张自动地图，换席位、换图种或换请求不能反复排队收费。工具原回执与地图记录原子保存，即使运行日志尚未写入，重放仍返回原输出，不把新ready状态冒充旧pending；新读取才得到当前状态。生成中断/失败不自动重试；主持撤下、校准或手工维护后，AI不能再次自动发布。坏记录保留并拒绝，不当作空记录覆盖。旧0..12运行不获得新工具。

新运行v14在写入/等待后缺最新 `context_read` 时只返回 `context_required` 及下一工具提示，不生成、不计费、不终止；模型应重读后再请求，不重复已执行行动。旧v13目录、拒绝行为和原回执不变。完整反馈与拒绝边界见[地图情境刷新](harness-runtime.md#地图情境刷新契约14)。

管理员可直接在工作台「AI 设置 → 地图图片服务」保存独立图片接口、模型和密钥并启用。保存本身不生图，不需要再解锁或探测；后续地图请求使用新配置，在途请求保留原快照。启动配置仍兼容，见运行包配置。未启用时返回不可用，不创建假图。真实制图质量仍取决于所选供应商。普通自动示意图保持“未标定”，不把默认5尺当真实尺度；v42局部战术图另有明确的本场范围与DM比例依据。

### 当前场景地图状态（契约22—41）

新运行每个模型请求附带安全的当前图状态；仅图片已启用且状态为 `missing` 时提供 `map_request`。模型应在探索确实需要空间示意时主动按需制图，不必等玩家索取；不是每次换场景都生成。已有已发布手工玩家图同样算 `ready`。排队/绘制中不重复申请，失败和撤下不自动重排。工具执行时再次核对状态，但已接受的原回执仍优先回放；旧0..21运行保持各自合同。详细模型协议见[契约22](harness-runtime.md#当前场景地图状态契约22)。

统一入口可显式指定独立图片配置：`pwsh -File scripts/launch-dicerealm.ps1 -Mode Test -ImageProviderConfig <配置文件绝对路径>`。这表示启用配置供应商，后续按需生成可能计费；未指定仍关闭图片。不会借用文字模型或旧 `imageModel`，离线模式不能启用。此接线不代表本机已有可用图片配置或真实出图质量已通过。

### 本地原图与扩展地图

[剧本库](adventure-library.md)可以随明确选择的剧本装入原图。原图携带可选`importSource:{sourceUrl,visualStyle}`：来源URL只作标记，服务端不会联网下载；视觉描述为可公开的配色、材质、线条等说明，不填写布局、秘密或指令。原图不使用生成供应商、参考上传或额度，导入后是`ready`、`attempts=0`，默认未发布；只有玩家版可以公开。已有原图不可用生成或再次导入覆盖，需要改动时新建修订。

导入入口为主持专用`POST /maps/{mapId}/import?requestId=<UUID>&expectedVersion=<地图版本>`，正文是raw `image/png`。先通过`POST /maps`保存带`importSource`的原图草稿（空prompt、空referenceImages），再上传PNG、关联地点并发布。导入复用32MiB/8192单边/33554432总像素校验；原图尺寸不要求64倍数，以实际PNG为准。重试使用同一原requestId、expectedVersion和PNG字节。图像内容文件先落盘，ready与回执随后原子发布；中断可能留下未引用文件，不会伪报成功。

旧13—41契约在当前地点有已发布原图时直接复用；v42按用途与尺度判断是否适用，城镇原图不会占用局部战术图的请求槽。未覆盖用途仍可按需生成：仅从核验为同一冒险文档（ID、版本、hash）的已发布玩家原图选择显式视觉描述，同地图类型优先，再按稳定ID选择；不使用主持版、未发布版、原图字节或私有prompt。新库安装将冒险/包/文件/PNG身份保存在地图记录；旧库图按确定性安装ID、现存包、同冒险文档和PNG哈希只读核验，不改旧Create正文或回执。来源无法核验（包括无关坏包）时不借用该图，仍可按公开资料生成。

生成规格的`generationBasis`冻结冒险身份、sceneId、stateVersion、作者当前变体描述、已采用的公开地点记录ID/revision/source/正文及合法公开出口。只采用preparation/dm/host地点资料，模型自行存下的叙述不算已确认地理。动态地点通过其公开源记录核对，不因SceneId为空丢掉已核实正文；出口只含已知目的地标题，不带未到达地点的详细描述。不得把私有具体位置写进负向提示。

`styleReference.snapshot`保存原图版本/contentHash、冒险身份与`referenceMode=description`。只借外观，不复制原地点布局；本轮没有上传原图像素。地图名称和公开`provenance:{kind,referenceMode,layout}`明确标注扩展示意、非原版地理，比例未校准另行显示，后续校准不会把它变成原版地图。完整输入仅host可读；公共投影不提供完整prompt或源图链接。默认不烘焙网格，不捏造门、支路、房间、掩体或未知障碍。生成ready+published后沿现有同版棋盘图片进入后续实际模型请求，不单独调用模型通知。

这些限制约束输入和标注，不保证图片供应商绝不添画内容；真实质量仍需看图，错误图可用既有主持撤回/修订入口处理。

### 当前工作台阅读入口

「内容 → 地图图册」按需读取原图或生成图，支持适应宽度/原始尺寸与滚动，并显示用途、比例依据、发布状态和来源。浏览与本地切图不写入、不生成。主持可编辑当前图的用途、网格跨度/偏移、真实距离/单位与依据，或用“两点标定”按实际图片像素取尺。保存尺度后地图撤下发布，检查后可重新发布；合格的当前场景玩家图可明确设为共享当前地图。网络结果未知时沿全局入口重试原请求，版本过期保留草稿，不自动覆盖新版本。切战役、离页与鉴权失败清理旧像素，不把凭证放进图片URL。

### 旧高级界面与仍保留的手工维护协议

以下记录旧高级界面和对应服务端能力；当前工作台已恢复上节的尺度标定和共享选图，其余创建、关联和标记编辑仍按服务端协议维护，不能按旧步骤寻找所有按钮。

1. 在旧同源主持工作台打开「剧情与地图 › 地图图册」，展开「高级：手工创建与维护地图」。填写名称、类型、版本、请求像素宽高与提示词原文，或选择自己的描述 JSON。
2. 设置用于阅读的网格与比例尺。地图范围和像素大小分开：同样的像素可以表示一间房、一个城镇或一片区域，范围由你填写的每格距离与单位说明。
3. 点击「保存地图草稿」。保存不调用模型。描述保存后不能覆盖提示词；需要修订时用「复制为新草稿」，旧图不会被覆盖。
4. 点击「确认生成地图」，检查尺寸、参考图与费用提示。取消不会发出生成请求；未配置供应商时仍可保存描述。
5. 图片就绪后，拖动、滚轮缩放或使用「适应窗口」「100%」检查。网格可以开关和校准，已经画进图片的格线不能由叠加层擦除。
6. 只有玩家版可以发布。检查图片里是否已有秘密入口、答案、房间备注，再明确「发布给玩家」。主持人版始终只对主持人开放。
7. Unity 在正文右侧常显约60%宽的地图区，可拖分隔线调整宽度；没有可读图片时显示真实空态或错误，不再收起/展开或另开大图。点击「地点 M」或按 M 只查看已知地点与路线，该页不再显示图片地图。图像滚轮缩放、拖动平移；当前场景地图自动确定，没有切图菜单，网格/测距/恢复全图收在「工具」菜单。即使当前席位是主持人，也不显示未发布图或主持图。可通行地点仍先进入原行动预览，确认后才旅行；没有地理定位的地点保持列表，不从生成图片猜坐标。地图详情仅显示所选地点的信息，不再拼接通用世界记忆或“冒险中记下的信息”。

工作台会在任务等待或生成时更新状态，不重建正在填写的下一张地图表单。网络中断后，请使用「重试原请求」确认结果，不要关闭仍有待确认记录的标签页。图片生成失败后，新的生成尝试需要再次确认，可能再次计费。

撤下地图会阻止后续读取，但不能收回玩家已经看见或下载的内容。网格校准或保存标记会撤下当前发布版本，检查后需要重新发布。图册维护不移动单位或结算移动、视线与探索；战术逻辑格从已保存的可靠尺度派生。活动战斗仍使用原冻结布局。

### 与游玩地点关联

旧高级界面中选中地图，展开「关联游玩地点」，勾选已启用剧本中的地点，再保存关联。可以选择多个地点；取消全部勾选后保存即解除关联。没有启用剧本的房间仍可制作地图，但不能借此创建地点。系统不提供默认关联，也不会改写导入的剧本。

Unity 主地图使用服务端 `selectedMapId` 指定的当前场景已发布玩家图；活动战斗以冻结的 `BoardLayout.MapId` 为准。非战斗时，没有明确选择或所选图已不可读，服务端按 `CreatedAt` 降序取当前场景合格图。活动战斗底图不可用时显示不可用，不改用其他图；新开战也按同一当前图取实际站位，不采用角色最后操作的其他地图。玩家与AI使用同一选择；较新的城镇图不会覆盖已选中的局部图。没有合格地图时显示真实空态，不回退其他地点，不保留旧场景图。玩家没有地图选择器、切图回调或“查看其他公开地图”入口；缩放、平移、网格、已标定测距及合法棋子操作仍保留。实现：[MapCatalog.List](../server/DiceRealm.Server/Infrastructure/MapCatalog.cs)、MapPresentation.CurrentSceneMap、AdventureMaps。

Unity 在空闲且没有待确认行动时随现有轮询同步地图元数据，不要求主持人再提交一次游戏行动。同一张图片未变化时保留缩放、平移和测量；慢图片下载不会被每轮元数据同步重新启动，也不锁住普通行动。正文右侧保留唯一查看器和纹理；地点、角色和手记不移动地图、不启动第二套下载。打开/关闭辅助页不销毁纹理、缩放与平移，拖宽保持行动草稿与聊天阅读锚点。

撤下当前地图后，下次同步自动采用同场景下一张合格图；没有合格图时清除图片，右侧保持当前地图空态，正文宽度不跳动；M页只显示已知地点。换地点立即清除旧图与棋盘，换席位/战役、凭证失效或读取权限未能确认时也清图。元数据和图片分别校验连接、场景及读取代次，图册 `currentSceneId` 与当前快照不符时等待同步，晚到响应不能恢复旧场景或旧地图。元数据失败随进度同步恢复；为避免未确认权限下展示旧图，失败时会清图，恢复后重新适应全图。图片失败显示明确重试入口，不循环下载坏图。图片只保留在当前会话内存中。

关联决定当前场景的自动显示候选，不触发生图、不改变发布状态、比例尺、角色位置或可通行路线。自动选图不是新的读取权限：API仍可返回其他地点已发布且有权读取的玩家图，主持工作台保留完整图册与明确的维护操作；发布前仍须审核图面秘密，不能依靠玩家界面没有切图入口保密。完整关联 ID 与可选地点列表只返回给主持工作台；玩家只获得当前地点 ID 与每张可读地图的 `currentScene` 布尔标记。

地点关联保存在战役自己的地图记录中，不属于生图描述 JSON，也不参与图片缓存身份。修改关联使用地图版本和原请求回执；断线时重试原请求，不会重复修改或重复收费。其他地图等待生成时，同一版本地图上尚未保存的关联勾选不会被图册轮询清掉。

### 地点、人物与任务标记

旧高级界面中选中地图后，展开「地图标记 · 地点 / 人物 / 任务」。点击「添加标记」，选择类型与已启用剧本中的关联对象。新标记默认仅主持可见；可填写横纵百分比，或开启「在图上定位此标记」后点击实际图片。拖动只平移，测距与定位互斥。键盘聚焦画布后可用方向键平移，定位模式中按 Enter 选择画面中心，Escape 退出该模式。

「保存标记（不生图）」只保存元数据。已发布地图会先要求确认保存并撤下；审核图片和标记后，再使用原有入口明确发布。标记引用已有地点、人物或任务，标题与说明取自后端当前信息，不提供自由填写秘密备注的捷径。坐标以实际图片左上角为原点，横纵分别为 0 至 100%；供应商实际返回尺寸与请求尺寸不同也不会偏移。

设为「玩家可见」还不等于立即公开：玩家必须有权读取地图，且后端当前已公开该关联对象。地点使用现有已知路线投影，人物和任务使用现有手记可见条件；主持私有、尚未知晓或已失效对象的标记不会下发。条件变化后的同步会更新标记及说明，不重置同图缩放、平移或测量。发布的图片本身不按这些条件遮盖，仍须主持审核图面秘密。

Unity 点击标记打开按需详情，或用 Tab 选中标记后按 Enter；Esc 关闭详情。人物和任务只供阅读，不代表实时位置，不自动触发对话或领取任务。地点只有在当前快照已有合法旅行选项时才显示「前往」，仍需原有行动预览和确认；阅读、关闭与取消均不推进冒险。测距时点击标记只测量，拖动不打开详情。撤图、换上下文或权限失效时，标记、详情和旧操作回调随地图一并失效。

未保存标记草稿按席位与地图保留在当前标签页内存，切换工作台页面、地图或同步图册不会清掉它；重新加载网页或关闭标签页前请先保存。外部地图版本改变时保留旧草稿并提示冲突，不自动覆盖或升级草稿版本；明确「放弃并载入」后才重新编辑。响应丢失时使用全局「重试原请求」，保留原请求编号、地图版本与标记；确认成功只清掉对应修订，不能擦掉较新输入。已保存标记随服务端记录跨重启保留。

### 自动公开关联信息

服务端与工作台新增独立 `automaticMarkers`：公开记录的SceneId可以沿用本图已有地点标记的位置，随记录修订自动更新，不改地图版本或生成图片。不把自动标记写回人工草稿；没有锚点保持未知，不提供实时人物追踪。动态路线、精确边界和Unity暂存/待交付状态见 [世界维护](world-maintenance.md)。

### 直线测距

Unity 的地图工具提供「直线测距」；工作台当前阅读入口提供两点标定，以下工作台测距键盘操作保留为旧高级查看器说明。开启后，在图片内点一次选起点，再点一次选终点。第三次点击重新开始；「清除测量」只清除端点，「退出测距」结束此工具。拖动仍然平移，不会误选终点。图片四周的留白不接受选点。

测量线记录图片坐标，缩放、平移、适应窗口和同图同步都不会改变读数。关闭叠加网格也可以测量。切换图片或清除私有图片时，测量一并清除；工作台关闭查看器也会清除测量，Unity 打开辅助页或专注阅读则保留主地图的测量。端点只留在本机内存，不保存到战役，也不发送给其他队员。

只有 `grid.uncalibrated` 为false或旧记录缺省、且依据不是显式 `unknown` 时才允许测距；未校准时已有测量也失效。旧的无网格但已有比例尺地图仍可测量。手工明确校准才可清除此标记，复制/导入草稿不能静默丢掉它。

读数按 `像素直线距离 × grid.distance ÷ grid.cellPixels` 换算，使用地图标注的单位。无网格、方格和六角格采用相同的像素比例尺；六角格的像素跨度仍指对角直径，不计算走过的格数。它不判断绕路、地形、视线或移动消耗，也不执行战斗规则。供应商图面可能失真，请先核对和校准比例尺，不把显示读数当成地图内容准确性的保证。

旧高级工作台查看器还支持键盘选点：先开启测距并聚焦画布，按 Enter 选择画面中心；方向键平移后可再次 Enter 选择终点。画面中心有十字标记，Escape 退出测距。Unity 使用地图内点选，出现端点后才显示清除入口；Esc 先关闭地图菜单，再退出测距。

### 描述文件

描述使用 UTF-8 JSON，单次请求最大 128 KiB。旧高级界面可下载空白结构、导出当前表单或导出已保存描述；当前图册阅读页没有这些入口。空白结构没有名称和提示词，填好后才能保存；系统没有地图故事、题材或文风模板。

编辑器提示见 [地图 JSON Schema](../schemas/map-v1.schema.json)，最终校验由 [MapCatalog](../server/DiceRealm.Server/Infrastructure/MapCatalog.cs) 执行。

| 字段 | 用途 |
|---|---|
| `title` | 名称，1 至 160 字符，不含控制字符 |
| `kind` | `world`、`region`、`settlement`、`dungeon` 或 `battle`，用于图册分类 |
| `purpose` | 可空 `region/settlement/tactical/schematic`；用途不决定比例，旧图缺省不回填 |
| `edition` | `gm` 主持人版或 `player` 玩家版，不自动删除图面秘密 |
| `prompt` | 生成图的完整提示词，1 至 16000 字符；原图必须为空 |
| `width`、`height` | 生成图为 256 至 8192 的 64 倍数；原图为 1 至 8192 的实际尺寸。总像素最多 33554432 |
| `importSource` | 可选原图来源URL和公开视觉描述；不是远程下载或模型调用指令 |
| `styleReference` | 服务端为扩展生成图保存的文字风格来源及可空snapshot版本/hash/referenceMode，只读，创建请求不能指定 |
| `generationBasis` | 可空、服务端冻结的公开空间依据，只在host完整规格返回，创建请求不能指定 |
| `grid.type` | `none`、`square` 或 `hex` |
| `grid.cellPixels` | 16 至 2048 像素。方格为边长，平顶六角格为对角直径 |
| `grid.offsetX`、`grid.offsetY` | 图片左上角起算的像素偏移，各为 -8192 至 8192 |
| `grid.distance` | 每格对应的正距离，最多 1000000 |
| `grid.uncalibrated` | 可选boolean；true表示未标定，禁止距离换算。缺省false保留旧图兼容 |
| `grid.units` | `feet`、`miles`、`meters` 或 `kilometers` |
| `grid.scaleBasis` | 可空 `{kind,detail}`；kind为source/dm/unknown，unknown必须未校准；缺省保留旧图“依据未记录” |
| `referenceImages` | 本战役已登记参考图的 SHA-256 数组，最多 4 项，不重复 |

六角格采用平顶、奇数列向下偏移半格。网格坐标使用实际图片像素；供应商返回尺寸不同或图内已有格线时，请重新校准。显示过密时会隐藏叠加线，放大后恢复。

手工生成请求只发送保存的 `prompt` 原文，不把类型、网格、比例尺或系统题材偷偷拼入提示词。如果希望图片画出俯视结构、房间编号、图例、网格或留白，需要在自己的提示词中明确描述。系统只提供接口和阅读工具，不保证模型懂得未写明的创作要求。

### 尺寸与供应商

请求尺寸不等于所有供应商都支持的尺寸。生成和参考编辑都发送 `size=<width>x<height>`、`n=1`，要求返回 `data[0].b64_json` PNG。供应商拒绝时报告失败，不换模型、不偷偷降分辨率。返回不同尺寸时保留实际宽高，两个前端显示差异，并按实际比例浏览，不强行拉伸。

Unity读取本机地图PNG复用JSON API的托管直连，避免Windows原生代理吞掉loopback图片；不改系统代理，远程仍走UnityWebRequest。固定同战役鉴权路径、无重定向、大小上限和哈希校验保持，撤图/换席位取消下载并清理临时文件。

有效成品最大 32 MiB、单边 8192 像素、总像素 33554432。服务端检查 PNG 签名、块边界、CRC 和尺寸。Unity 与浏览器在解码前检查字节上限、内容 SHA-256 和实际尺寸；Unity 的私有地图不进入旧公开场景磁盘缓存。

| 配置 | 行为 |
|---|---|
| `ImageAi__ApiKey`、`ImageAi__Model` | 未保存工作台图片配置时的bootstrap；与文本配置独立。工作台保存后使用独立Image配置 |
| `ImageAi__Endpoint` | OpenAI-compatible 生成 endpoint |
| `ImageAi__SendResponseFormat` | 默认 `true`，发送 `response_format=b64_json`；兼容不接受此字段的供应商时可设为 `false` |
| `ImageAi__EditsEndpoint` | 可选 multipart 编辑 endpoint，不根据生成地址猜测 |
| `ImageAi__AllowReferenceUpload` | 默认 `false`；显式允许后才外发已选择的参考 PNG |
| `ImageAi__TimeoutSeconds` | 默认 180 秒，限制为 15 至 300 秒 |

旧 `ImageAi__MaxAttempts` 配置不再控制地图：每次确认最多外发一次，不自动重试超时、断线或 5xx。服务启动后，残留的 `generating` 地图标为失败，不重新发出可能已计费的请求；已经确认但尚未认领的 `pending` 地图可继续执行。供应商身份改变时，旧排队任务失败，等待重新确认。

供应商可能已处理但响应丢失，本地请求回执不能保证供应商账单的 exactly-once。请先看任务状态与供应商账单，再决定是否重新生成。

外部 endpoint 需 HTTPS；测试适配器可使用 loopback HTTP。重定向不会跟随，供应商返回的任意图片 URL 不会被下载。参考编辑只发送当前战役已登记的 PNG，不接受服务器路径或远程 URL；单图字段为 `image`，多图为 `image[]`。

地图形态参考了 5etools 的区域（六角格、英里比例）、城镇（街道与建筑）和地城（房间、通道、方格与编号）地图，以及其“主持人版/玩家版分开、宽高/网格尺寸/偏移独立记录、缩放与适合窗口”的做法；基础程序只借鉴结构；用户明确安装的本机冒险包可以携带其原图，来源和使用范围随包记录，不能据此公开再分发商业素材。

### 参考图与额度

主持人通过 `POST /api/v1/campaigns/{id}/references?name=...` 上传 raw `image/png`；读取元数据使用同路径 GET，均需主持人 Bearer 凭证。上传最大 10 MiB、4096×4096，每战役最多 64 个内容哈希。登记只在本机保存，不等于授权外发；生成确认和服务端参考上传开关仍分别检查。旧的已就绪场景图片也可通过兼容接口登记，见 [旧场景兼容说明](scene-assets.md)。

工作台显示文本与图片调用额度。[ProviderBudget](../server/DiceRealm.Server/Infrastructure/ProviderBudget.cs) 在 HTTP 发出前持久预留次数，失败与手动重试计数；缓存命中、离线或外发前校验失败不计数。预留后崩溃可能计数而未发送，不自动退款。

| 配置 | 含义 |
|---|---|
| `ProviderLimits__TextDaily` | 全数据目录 UTC 日文本次数 |
| `ProviderLimits__TextCampaignDaily` | 每战役 UTC 日文本次数 |
| `ProviderLimits__TextTotal` | 全数据目录累计文本次数 |
| `ProviderLimits__ImageDaily` | 全数据目录 UTC 日图片次数 |
| `ProviderLimits__ImageCampaignDaily` | 每战役 UTC 日图片次数 |
| `ProviderLimits__ImageTotal` | 全数据目录累计图片次数 |

每项默认 −1（不限），可设置为 −1 至 1000000，0 阻止对应调用，非法配置拒绝启动。旧场景调用计数保留，地图使用同一本账，不因重启、新建战役或换模型重置。次数不是金额，也不代替供应商预算。

### HTTP 与保存

以下路径以 `/api/v1/campaigns/{id}` 为前缀，均需有效席位凭证。

| 接口 | 请求或行为 |
|---|---|
| `GET /maps` | 主持人得到全部地图及自己的描述；队员仅得到已发布玩家地图，不含提示词与参考列表 |
| `GET /maps?publishedOnly=true` | 主持人也使用玩家投影；Unity 使用此接口。返回 `currentSceneId`、可空 `status`（见下）和每张地图的 `currentScene`，不含 `sceneIds`、`sceneOptions`、`markerOptions` 或提示词 |
| `GET /maps/{mapId}` | 读取有权访问的地图状态 |
| `GET /maps/{mapId}/image` | 鉴权 PNG，`Cache-Control: private,no-store`，不支持公开哈希访问 |
| `POST /maps` | `{requestId, specification}`，保存草稿，不生成 |
| `POST /maps/{mapId}/import?requestId=…&expectedVersion=…` | raw PNG，原图草稿一次导入；幂等指纹包含PNG内容哈希，不生成 |
| `POST /maps/{mapId}/generate` | `{requestId, expectedVersion, confirmProviderUse:true}` |
| `POST /maps/{mapId}/publish` | `{requestId, expectedVersion, published, confirmPlayerVisibility}` |
| `POST /maps/{mapId}/grid` | `{requestId, expectedVersion, grid, purpose?}`，用途与尺度一同保存，不改像素、不调用模型 |
| `POST /maps/{mapId}/select` | `{requestId, expectedVersion, expectedMapVersion}`；这里expectedVersion为战役版本，明确选择当前场景公开图，不移动单位 |
| `POST /maps/{mapId}/scenes` | `{requestId, expectedVersion, sceneIds}`，仅接受已启用剧本地点，最多 128 项且不重复；空数组解除关联 |
| `POST /maps/{mapId}/markers` | `{requestId, expectedVersion, markers}`，完整替换标记数组并撤下发布；空数组移除全部，最大请求体 128 KiB |

图册的可空 `status` 仅含 `{sceneId,status,generationEnabled}`。状态为 `unavailable/missing/pending/generating/ready/failed/withheld`；未配置、离线或归档不允许新申请，但已有已发布图仍可读。`ready`优先识别当前关联且可读的玩家图，不要求自动来源。该字段不含未发布地图ID、prompt、参考图或错误正文，`maps`数组仍只放玩家有权读取的图。读取和打开页面不入队、不写游戏、不调用供应商；Unity缺旧字段时显示未记录/未启用信息，不伪造生成进度。

主持人普通 `GET /maps` 另含 `sceneOptions:[{id,title}]` 和 `markerOptions:[{kind,targetId,label,playerVisible}]`，其地图记录含 `sceneIds`；尚无已启用剧本时选项为空。`markerOptions` 只给主持工作台，不进入玩家投影。

标记输入为 `{id,kind,targetId,x,y,visibility}`：`id` 是不重复的非空 UUID（标准 D 格式）；`kind` 仅 `scene/npc/quest`，`targetId` 必须属于当前战役已启用内容的对应类型；`x/y` 为有限的 0 至 1 数值，分别相对实际图片宽高；`visibility` 仅 `gm/player`。每图最多 128 项。非法引用、类型、权限或坐标返回 400 `invalid_map_markers`；超过请求体上限返回 413。多余 JSON 字段不被接受。

每个地图响应新增 `markers` 数组，在输入字段上附带后端投影的 `label/summary/state`；旧地图默认为空。队员的列表与单图读取、主持的 `publishedOnly=true` 列表都执行相同公开过滤；没有可见目标上下文时不返回玩家标记。已失效引用可在主持界面删除，玩家不可见。返回中不附加任意可执行命令。

除共享选图允许已获准席位外，以上地图维护写入仅主持人可用；AI自动图走受限的 `map_request` 工具，不冒用主持身份。维护请求的 `expectedVersion` 是地图版本；`select` 同时绑定战役与地图版本。所有请求 ID 为非空 UUID。重复的同一请求返回当前地图，不重新执行；同 ID 不同内容返回 `map_idempotency_conflict`，过时的新操作返回 `stale_map`。已接受请求在归档后仍可确认，新操作被拒绝。

[MapCatalog](../server/DiceRealm.Server/Infrastructure/MapCatalog.cs) 将描述、状态、发布标记、地点关联、图上标记、任务租约和请求回执保存在同一个原子记录中。数据位于数据目录的 `maps` 与 `map-images`；请和战役数据库、旧资源及额度账本一同备份，不要单独删除索引。每战役最多 128 张地图，不自动淘汰；需要改变已就绪提示词或尺寸时创建新草稿。

缓存身份包含完整提示词、请求尺寸、参考图顺序和供应商身份。标题、显示网格、地点关联与图上标记不触发重复生图，也不改变缓存身份。相同请求可跨战役复用文件，但每个战役的读取权限独立。文件校验按内容哈希、长度、修改时间和创建时间缓存，避免每次图册同步重新读取所有大图；客户端仍独立核对哈希。

### 参考与验证边界

界面参考了 [5etools Maps](https://5e.tools/maps.html) 中区域、城镇、地城的分层用途，主持人/玩家版本、网格偏移与缩放阅读。基础运行包不内置5etools商业地图或其完整查看器；本机明确安装的模块原图独立注明来源，不构成公开发行许可。

自动化以离线 HTTP 适配器和程序生成的校准测试图覆盖不同尺寸、原文传输、请求丢包重放、发布权限、网格校准与读取；测试图明确标记为 QA，不能当作模型出图质量样张。真实供应商对大尺寸的支持、提示词质量、参考编辑效果和地图制图准确性需由实际配置单独验证。
