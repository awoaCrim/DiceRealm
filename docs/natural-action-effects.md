# 主输入中的可执行效果

规则来源为固定 `dnd2024` 本地文件，修订 `e5f3e77b303a92df10487207857200245e71957c`；核对入口 `scripts/verify_natural_action_rules.py` 只读固定哈希，不联网、不调用模型。标准战斗见 [standard-combat.md](standard-combat.md)；跨角色目标不包含在本页承诺里。

## 当前会实际执行什么

玩家从主输入表达意图，系统提供带目标、来源、资源及骰子说明的候选。本人确认之后服务端才投掷并同时保存 HP／状态、资源／物品、事件和回执，不需要主持再补一次账。

| 效果 | 当前规则与边界 |
|---|---|
| 回气 Second Wind | 自身恢复 1d10 + **Fighter 职业等级**，消耗一次 Second Wind；多职业总等级不替代 Fighter 等级 |
| 治愈之手 Healing Hands | Aasimar 自身恢复 PB 颗 d4，消耗该物种资源一次 |
| 圣疗 Lay on Hands | Paladin 按已持有池选择确切点数，至多当前缺失 HP；或单独花 5 点解除自身 Poisoned，后者不回血 |
| Potion of Healing | 明确绑定的 XDMG 标准治疗药水，一瓶恢复 2d4+2；同名、相似 ID 或无来源绑定的物品不自动当药水 |
| Cure Wounds | 当前已准备／取得的具体来源，恢复 2d8 + 此来源施法属性调整值；用更高法术位时每环 2d8；只治疗自身 |
| Healing Word | 对自己可见时，恢复 2d4 + 此来源施法属性调整值；用更高法术位时每环 2d4；只治疗自身 |
| Lesser Restoration | 选择解除自身已记录的一个 Blinded／Deafened／Paralyzed／Poisoned；施法者仍须有行动能力，所以不能以自行施法绕过 Paralyzed |

治疗不超过最大 HP，不恢复临时 HP。Life Cleric 的 Disciple of Life 在确实使用法术位时额外恢复 `2+环级`；17级 Supreme Healing 对治疗法术使用最大骰面并明确记录**未掷骰**，不作用于回气／药水／物种能力。对自身施法不触发只治疗他人的 Blessed Healer。

这些是**非战斗、自身效果**。S 成分采用保守的空手限制：当前不能准备着武器或盾牌；可以先通过已有换装操作收起。护甲必须受训；V 成分需要能发声，未记录的沉默／束缚等阻碍须先核实，不能把不存在的场景几何当成许可。0 HP、无法行动、非致命击倒恢复阶段不能自行使用。条件触发型来源、仪式、材料法术、其他药水等级与他人目标没有因本次接线获得自动执行能力。

每次确认的探索效果经过 6 秒。这是项目的探索记时单位，不宣称所有 D&D Action／Bonus Action 单独耗时 6 秒。战斗会使用独立回合预算，不能绕过它调用本页操作。

## 角色窗口中的相同效果

`character/sheet.effects`可空数组提供`key,label,itemId,spellSource,details`，由同一个NaturalActions投影，读取0副作用。背包按精确itemId提供“使用…”，来源法术按精确spellSource关联；在本人看到来源、目标、骰子和成本后确认`operation=execute,key=<完整key>,value=1`。客户端不计算HP/资源，不从同名药水或法术名称猜执行路径。无effect的物品只回填自然输入草稿，不覆盖旧稿、不自动提交裁定。

新自然解释和工具契约12及以后不再提供通用use/spell/feature记录候选：已有完整规则直接执行，非机械活动正常叙述，缺依据先澄清，确实需要人工判断的疑难仍保留裁定入口。并不因此新增本页表格以外的效果或跨角色目标。

## 导入物品的规则身份

`AdventureDocument.items[]` 可明确填写：

```json
{"id":"local-red-vial","name":"红色药水","rulesId":"xdmg:potion-of-healing"}
```

当前只接受这一完整执行条目。省略或 null 仍是旧的叙事物品，null 不参与序列化，旧剧本绑定哈希保持。物品 ID 必须真实在当前角色库存且数量大于0；只查读规则、世界手记出现名称、模型声称获得药水都不能创建它。奖励仍通过已导入并启用的剧本／授权角色调整取得，模型不提交 rulesId 或效果数值。

## 已记录检定的剧情后果

原本的导入行动在检定确认后已经自动应用对应后果，不要求多一次主持操作。新增分支用于当前自然行动此前经过裁定并得到真实检定的情况：只有本人、同一输入 root、原场景、同属性／技能／DC 的已完成能力检定才能提供匹配剧本的后果候选。成功或失败来自原检定，模型不能选择或改写。

确认后只应用已启用剧本的对应分支，更新事实、章节、队伍奖励及由它们派生的任务／合法路线。奖励沿用现有约定进入队长库存。一次性 action 和该 ruling 的 Story 都被标记，不重掷、不重复领取。无检定结果、其他输入的旧检定、换场景、已做角色效果调整、含负物品成本等无法排除重复补账的情况不会自动落实。主持的任意事实修正入口继续要求主持权限。

## 兼容与请求

自然效果最初引入工具契约 **8**；当前新增运行使用 **16**（`HarnessTools.CurrentVersion`），旧版本目录与指纹冻结。旧0..7运行的候选投影不包括effect／story，旧8..11保留其记录型候选，不因新程序启动就升级。v7 golden 为 `1adde70c276a586a72a1be091e7fd7af5f237ee07ebc2496cf0a69ad2a6426e4`，来自修改前程序集。

新效果通过既有 `context_read`／`actions_list` 返回类别 `effect`，用原 `actions_propose(candidateId)` 选择并停止等待。本人继续用 `/intents/respond` 选择实际 optionId；没有新增可由模型填写 HP、骰子或资源名称的工具。内部角色命令使用 `operation=execute` 与完整服务端 key，`value` 必须为1。旧 `use`／`spell`／`feature` 仍是原先记录／裁定语义，原请求和回执不改写。

来源／资源／自身状态变化返回 `action_unavailable` 或当前意图过期冲突，不补骰、不消耗。重启后仍返回原回执；不同 requestId 抢同一版本只提交一份。客户端仅展示原候选详情和回执，不新增机械状态算法。

Unity沿用现有通用候选／确认 DTO，不需要为这些类别增加字段。
