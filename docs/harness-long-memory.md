# 历史上下文与原文回查

新运行使用契约45的父端历史策略；旧0..44运行、战斗会话及模型槽位保留原合同，不自动迁移。既有关键词召回见[工作区](harness-workspace.md)，运行恢复见[Harness](harness-runtime.md)。

## 契约45：只整理已经结束的历史

系统提示、完整主持提醒、工具合同、当前意图、已接受步骤、等待关联和当前未完成的原生工具链始终完整保留。新模型槽位重新读取权威快照与同版棋盘；历史不推导当前位置、装备、生命或资源。Gemini有序Part、调用关联和thoughtSignature由供应商适配器原样续接，思考不提炼为故事。

父端采用Magic Context的分层摘要、近期原文和确定范围发布机制，使用项目原有Run、Session与SQLite持久化。上游没有独立公开HistoryManager SDK，本实现没有安装其编码宿主插件、深层导入或复制其默认裁剪器，也不开跨项目共享、dreamer或第二套游戏状态库。固定上游参考为0.49.11、commit `5a68e73cddb3db0080ee5910a96904fb0f8e86e3`；核实记录见任务的`magic-context-research.md`。

### 默认提供来源历史，相关原话不藏在搜索后

来源先分公共与当前角色私有，再规划摘要。公共部分包含其他席位实际公开的交流；私有部分只取本人获知的片段与本人已完成输入的问答，不遍历他人的私人Run，不使用主持代读权限扩大受众。当前交互、最新完整交流组、与本轮输入及相关人物匹配的整组原文受到保护；其余已闭合内容可使用摘要。已保存continuity以`model_reported_*`标识提供，不变成已验证事实。长历史中的通用词不会仅凭词面重叠把全部摘要来源补回；明确引文、已知发言者和当前人物的整组原文另行保护。

每份摘要持久保存精确`source.kind/id/part/revision`、scope、受众、版本、发布号、完整detailed/brief正文与替换关系。基线合并可与旧增量引用相同来源；单次请求、同一受众只选互不重复覆盖的组合。当前交涉引用已被摘要覆盖的原话时，显式标为“相关原文补充”。来源更正、受众或时间线变化后必须重新核对，旧摘要不能继续替换已变化片段。

新`ctx_search(query, offset, limit)`在当前授权来源中查找；`ctx_expand(source, offset, limit)`按精确来源和修订展开原文，分页不授游戏执行权限。源正文永久留在原事件、输入和回执体系；历史资料、摘要和角色台词不会取得系统指令地位。

### 摘要与模型槽位分别冻结

已结束历史在离开场景、结束回合或同一Run连续两次正常响应，或同席位、scope、时间线、配置资料与规则版本的历史Run首槽位，观察到实际输入token增长时，可由辅助模型后台整理。每次仅选择未覆盖、非保护的完整交流组；保留已发布基线并追加增量，不因旧边界仍在而重写整史。historian一次只接收一个受众的确定来源，没有游戏工具或状态写权限。指令要求保留说话人、条件、否定、知情范围、承诺和未回答事项；人物声称、考虑、失败与未采用计划不能变成已成立事实。brief同样要求保留全部并列条件、先后条件、后续义务和未决问题。清单不得从未承诺扩写新问题或义务，已知否定与触发条件不降格；sequence/version是来源定位信息，不是对话轮数。实际语义仍须对照原文，指令不保证任意生成正确，见下文验收结果。

生成成功、持久化并复核来源后，摘要才可替换原文。新槽位选择当前可用组合；已经开始的槽位冻结frame、摘要版本与层级、原文范围、工具和图像，不因后台发布而改变。同槽位允许的HTTP重试使用相同请求正文；done回放原回执，unknown不补发。每次主模型或辅助摘要生成外发仍重新授权。两者复用同一有限重试循环，默认首次之外最多3次，1/2/4秒退避；辅助摘要重试冻结来源、受众、配置和正文，逐次计账及记录日志。取消、撤权或不可重试错误立即停止；只重试当前活跃调用，不恢复已结束的unknown。

SQLite schema3保存派生摘要和工作状态，首次写入前迁移备份。游戏存档包含摘要；读档复核来源并隔离旧分支发布。`harness-issued/<campaign>/history.json`只记录外发来源范围、供应商身份与状态，不含原文，且不随读档/重开回退，防止未知摘要调用被再次发送。完整备份须保留整个数据目录。

### 正常响应usage与失败行为

主模型和历史摘要使用已配置的Gemini `generateContent`或OpenAI Chat `chat/completions`。不额外请求模型元数据或`countTokens`，不做本地token估算。主响应的Gemini `usageMetadata.promptTokenCount`或Chat `usage.prompt_tokens`随done槽位保存在私有`contextPlan.reportedInputTokens`；缺失为null，首次或缺usage仍正常生成。供应商实际用量继续记账，缺失输入/输出计数不以字节补造。旧0..44的记账兼容行为保持。

实际输入量用于后续槽位判断增长，不代表模型窗口，也不能保证下一次任意长请求都能容纳。不使用累计run.Tokens、虚拟桥128000、固定100k或比例作为容量。旧45候选的`inputBudget`只保留读取兼容，新调用不生成该字段。新45去掉OpenAI兼容Chat的预算未知硬拒分支；完整Pi工程验收以Gemini为准；step-5-preview另通过现有OpenAI Chat完成有限语义、私有摘要和真实Pi短工具循环验证。最新长历史Pi回顾与私密分投已完成，但仍漏述几项关系和承诺边界，不能用链路成功代替语义全项验收。

| 情况 | 实际行为 |
|---|---|
| 首次调用或正常响应缺usage | 正常生成；未知usage保持null |
| 没有摘要模型，或新摘要失败/未完成 | 在技术传输边界内使用原文/已发布组合，不等待后台 |
| detailed超过技术传输上限但完整brief能容纳 | 使用完整brief，不裁片 |
| 历史与现有摘要均超过技术传输边界，必需部分能容纳 | 等待受限整理；仍无法完整发送则`harness_context_preparation_failed`，不外发required-only占位 |
| 受保护的当前内容自身超过技术传输上限 | `harness_transport_limit`，不裁当前链 |
| 供应商拒绝实际请求或调用结果未知 | 沿原供应商错误/unknown处理，不删正文自动补发 |

父端完整准备正文的技术边界为4MiB，HTTP另保留既有图像体积限制；Node回调1.5MiB、wire行2MiB仍是传输限制，不是token窗口。读取工具可在形成结果前沿原合同分页，已经接受并保存的当前原生结果不再事后裁剪。失败提示说明本次后续回应未完成、已保存行动与骰点保留，不声称行动全部没发生，也不建议重复执行。

### 探索与战斗分别规划

探索和每个战斗Session独立选择历史，当前输入原生链保留，旧已结束输入通过来源资料承接。原Handoff提供交锋原因、意图、动机与真实结果；战斗只整理已结束回合。主代理挂起时不接收逐刀工具对话。

结束时在原Return事务冻结公开/本人叙事、问答、接受的连续性笔记和未完成事项，并提供已保存回合/行动种类概括及实际结束记录。主代理读取最新权威状态，不按摘要重新结算。后续探索仍可取得本人合法战斗叙事；逐次机械结果留在`combat_history_read`。恢复、return消费和去重继续由原Run/Session拥有。

验证入口为`HarnessGeminiTests`的protected context组、`HarnessHistoryTests`、`HarnessHistorySummaryTests`、`HarnessHistoryPipelineTests`及战斗/存档回归。受控HTTP验证覆盖完整实际请求、权限、冻结、失败表与重启。真实摘要检查发现Gemini brief会漏部分关系。后续Step对照查出临时消费者缺ruleset、没有进入产品既有中文展现路径，旧消费端失真结论仅适用于该转义输入。补齐标准包络并收紧清单/序号指令后，Step的65组虚构历史详/简摘要及只读消费通过有限关键语义验收；真实Pi短房完成原文搜索、展开和私密分投。启用三次重试后的新长房确实选中两摘要＋2近期原文、0旧文补充，首次请求即成功，真实Pi执行world_record并只向本人交付私密内容；原请求重放零外发。最终回顾遗漏了摘要中实际保留的岑野戒心、黎桑关系边界、方榆不信传闻和莫砚未承诺钥匙，剩余为主模型回顾覆盖，非摘要丢失或网络阻塞。此前两个网络unknown保留、未重发。输入范围、实际usage与证据修正见Step检查。

## 旧0..44：自动跨行动记忆

新运行创建时，在已授权战役锁内从 `HarnessMemories.Eligible` 选取**本人、已完成、已公开、有最终结果**的行动。仍包含有界近期记忆，同时可在 `memory.archive` 中携带较早行动的抽取摘要：`method,totalOlderActions,selected`。先按本次输入的相关性选择，再补充跨时间段的少量记录。整份初始记忆仍限制24KiB，按UTF-8实际序列化体积缩减，不把最近12条扩大成整库外发。

`selected` 每项是 `intentId,originSequence,resultVersion,input,narrative,corrected,steps`，其中输入160字符、叙事480字符、最多两个已结算步骤及每步160字符。摘要是保留原词句的**截取**，不是推导出来的新事实；可能未包含重要后文。使用 `memory_read(intentId)` 查完整原文和原检定。否定词、未完成计划不能被改写为成功。

当前公开更正替换可检索/摘要中的叙事，不发更正理由，不重写原骰点、消耗或旧运行。初始快照一经保存即冻结。其他席位、私有草稿、取消/未结算输入不加入，主持也没有旁路。旧运行没有 `archive` 字段，null省略，旧初始Turn与回执不升级。

## 来源化工作记忆（契约23）

v23在原全文日志和冻结MemorySnapshot之上，仅为新供应商请求派生`HarnessWorkingMemory`。仍限本人已完成公开行动，近期窗口12条：最近2条保留有界原文，较早条目优先使用同事务提交的连续性笔记；更老历史沿用原相关性/时间锚点选择，coverage报告总数、遗漏和缩减。完整原输入、叙事、权威步骤与回执没有被这份投影覆盖。

`world_record.continuity`可同时提交最多8条`{kind,text}`，kind为`observation|statement|promise|relationship|open_question`，每条≤240字符；同一行动精确去重后保留最后16条。这些是模型记录，不是已验证机械事实，承诺不等于履行。它们不额外调用总结模型，也不自动替旧记录生成语义总结。公开更正存在时不继续使用被更正的旧笔记。

没有笔记的旧档保留带行动ID、版本、源偏移/长度和截取标记的正文摘录及引号所在完整短句，不能仅摘“答应了”而丢掉句外“没有说过”。过长、无法在边界完整保留的引号上下文宁可遗漏并报告数量，不能改写成肯定事实；必要时`memory_read`读全文。检定/权威步骤保留原ID与结果，不由笔记替代。整个工作记忆按实际provider编码控制24KiB，缩减及来源覆盖显式报告；外发省略零值审计元数据时有对应notice。

v23的`memory_read`补充continuity、实际接受的获物来源和`extrasCoverage`。到48KiB结果边界时先减少这些附加记录，保留原输入/完整叙事并报告总数，再沿原合同处理过多步骤；旧契约输出不增加字段。`memory_search`等仍是来源入口，命中不授执行或新奖励资格。角色/当前NPC及私有场景资料的边界见[契约23](harness-runtime.md#最终回应来源与工作情境契约23)。

## 只读工具

### `memory_semantic_search`

参数：`query`（必需，0..240字符、无控制字符），`offset=0`（非负，不能超过结果数），`limit=6`（1..8）。返回 `version,scope,algorithm,totalMatches,entries,nextOffset`。每条包含 `score,concepts,entry`；`entry` 为上述源记录摘要。

算法 `local-concept-lexical-v1` 结合有限的中英文概念特征与词项特征，通过加权向量相似度排序。例如“口令”可找回“守卫告诉我们暗号”的记录，英文 `passphrase` 也可命中，无须所有查询词逐字出现。完全匹配增加相关度，同分按原行动序号和ID稳定排序。

这是**有限领域的本地语义匹配，不是通用神经嵌入或另一个模型**。未知同义表达可能漏检，含相同概念的无关记录可能出现；分数不代表事实可信度。结果是引用入口，必要时改用原关键词工具、按时间摘要或完整读取。查询在当前授权投影上派生，不持久存放跨席位向量缓存；扫描成本随符合资格的历史增加，不声称已有大规模数据库全文/向量索引。

### `memory_digest`

参数：`before=0`（0表示最新，正数必须不超过当前游戏版本），`limit=8`（1..8）。返回 `version,scope,method,totalEligible,entries,nextBefore`。按原行动序号逆序给出自动抽取摘要，`nextBefore` 继续更早记录，不以近期12条限制查询范围。`totalEligible` 是历史数量，不表示本页已经概括所有历史。

两个工具最多24KiB，缩页仍推进游标；翻页必须保持同一查询和版本。它们不写游戏、不掷骰、不调用供应商，也不授予行动或世界对象更新引用。新工具只在契约5提供；契约0..4的名称、描述、schema、原输出与恢复不改变。

## 旧5..44：活动运行的自动压缩

`HarnessContextCompactor` 只派生**新模型请求**的上下文。Node保存/重建的完整transcript、父回调指纹、原Turns、Steps和工具回执都不改。预设system原文也不改。

当原请求与原生续接元数据的保守体积超过96KiB时，按时间从较早的完整 `assistant + 全部tool结果` 交互组开始替换为带原消息区间、source hash、工具ID/名称/内容hash和明确截取标签的用户数据。原始用户目标、本人答案和确认结果全部保留；不会保留悬空functionResponse或拆开一个并行工具组。摘录明确要求重新读取完整/当前证据，不能把摘要中的旧ID直接当执行许可。

Gemini保留下来的assistant仍使用原始有序parts/signature。`ProviderHistory` 随保留索引筛选；即使所有旧assistant都被摘要替代，父进程也保留所有原供应商身份用于校验，不能借压缩更换模型/端点。OpenAI不能把原生Gemini历史当普通文本接走。

压缩说明 `HarnessStep.contextPlan` 在外发前与started槽位一并保存，仅为私有运行审计，不进入前端。压缩会使当前候选、完整context已读标记和世界引用失效，下次需真实重新读取，不能返回已经被摘要丢弃的 `contextUnchanged`。缩减后仍无法容纳不可分割的system/用户内容时明确拒绝，零外发，不擅自截断预设。

此机制不启用Pi SDK自动压缩/重试，不新增总结模型费用。实际供应商仍检查完整HTTP body的128KiB上限，预算、16次模型/32次工具及超时均不增加（累计 Token 续发阈值已取消）。压缩不让已started但未知的模型槽位变得可重发。

## 旧策略的内部传输与兼容

wire1的run可选 `contextPolicy:"parent-compact-v1"`；仅契约5新运行设置。旧run省略，Node仍按原128KiB回调限制拒绝。新标志仅允许有界原始模型回调最多1536KiB送到父进程派生，不改变2MiB帧限额或供应商上限。工具回调限额不变，未知policy拒绝。

公开HTTP/Unity/工作台不新增内部配置面板；这些客户端继续发送同一业务输入、本人确认与恢复请求。无新增数据库权威表或自动迁移。

## 旧策略的拒绝与验证

- 坏查询/游标/数量：`harness_invalid_payload`；旧契约使用新工具：`harness_tool_unavailable`。
- 权限、撤权和游戏版本沿用 `unauthorized` / `stale_version`；未知或损坏压缩说明：`harness_corrupt_run`，保留文件。
- 不完整/不匹配的工具组：`harness_model_contract`；不可压缩到安全体积：`harness_context_limit`，不自动扩大预算。
- 已外发结果未知：继续 `unknown/harness_model_unknown`，重开、GET、同请求重放不追加调用。

`HarnessLongMemoryTests` 覆盖1200条历史及完整摘要分页、中文/英文改述、纠正/隐私/字节边界、候选不授予、原交互不改、真实Pi/MCP大上下文压缩→重新完整context→等待→重开→精确重放，以及压缩后unknown和坏记录保留。`HarnessGeminiTests.CompactionNativeHistory` 验证原生parts/signature对应和全摘要后仍不能换模型。旧契约4目录hash来自修改前程序集，0..3沿原冻结测试。以上供应商为fake，不代表真实模型语言质量。
