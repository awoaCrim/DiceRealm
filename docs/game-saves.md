# DM 存档、读档与重开

在主持工作台打开 **存档与重开**。只有 DM 可以管理整场游戏的存档；玩家端负责同步恢复后的进度，不提供存档菜单。

## 保存和恢复全队进度

- **新建存档**：输入名称并保存。列表显示保存时间、场景和队伍；选中后可看各角色的等级与死亡状态。
- **读取此存档**：全队回到该档位的游戏进度。替换前自动保留当前进度作为恢复点。
- **用当前进度覆盖**：替换明确选中的档位，保留档位名称。确认时核对该档位的修订，避免覆盖另一次保存。
- **删除存档**：只删除选中的档位，不改变正在玩的进度。
- **重开游戏**：按当前采用的剧本和队伍的初始建卡重新开始，清除进度与死亡状态。重开前也会自动保留恢复点。

新建只需命名保存；读取、覆盖、删除和重开各在实际操作处确认一次。存档名称最多 80 字，没有档位数量额度。

读档与重开保留房间和当前合法连接，不要求玩家重新建卡、重新加入。已撤销的席位不会因读旧档恢复权限。存档后新加入的角色仍保留自己的席位，以初始角色进入恢复后的场景，不继承其他人的私人信息。

## 存档包含什么

存档保存角色数值与行囊、场景与世界状态、战斗和待确认事项、完整历史、已知信息与私人正文、地图元数据及提示词工作区。历史不限于普通快照显示的最近一段。

账户、房间凭证与撤销、供应商设置及已发生的调用费用不回退。图片等不可变素材保留原引用，读档不会重新生成。

正在等待玩家投掷或确认时可以保存；模型正在执行时，工作台会说明当前正在结算。等结算结束再保存或恢复，避免截取半份调用结果。已经掷出的骰点和调用结果未知的记录按原状态恢复，不因读档自动重掷或重发 AI 请求。若后续分支曾调用 AI，而旧档位尚未保存那次结果，原运行显示结果未知；停止原行动后可用新的输入继续当前处境。已结算的战斗结果仍能完成交接，不重复结算。

## 断线和旧页面

提交后没有收到确认时，保留 **重试原请求**。重试使用原请求身份、正文与所属进度；即使读取存档已经成功，也只确认原回执，不再读第二次。

DM 读档或重开后，客户端重新读取故事、地图、角色与待办。旧进度里尚未确认的普通行动会过期，不能自动补发到新进度；原请求证据保留。同步完成后可以主动发起新行动。

## 死亡与游戏结束

死亡依据服务端记录的 `Dead` 状态。生命为 0、正在进行死亡豁免或已稳定但仍倒地，都不直接算作死亡。

已死亡角色不能发起或续接行动、投掷、换装或转述。直接向接口提交也会被拒绝，不进入 AI；已发送操作的原回执仍可核实，残留等待仍可取消。玩家可以继续阅读与观看队友的冒险。

有效、已批准且未撤销的玩家全部死亡后，双端显示 **游戏结束**。无玩家的空房不会被判全灭；无角色 DM 不计入队伍。结束状态保留，DM 可通过读档或重开恢复玩法。

## API 与客户端接入

以下路径均以 `/api/v1/campaigns/{id}/` 为前缀，要求当前 DM 授权：

| 操作 | 请求 |
|---|---|
| 列表 | `GET adventure/saves` |
| 新建 / 覆盖 | `POST adventure/saves`：`requestId, expectedVersion, name`，覆盖另带 `saveId, expectedSaveRevision` |
| 读取 | `POST adventure/saves/{saveId}/load`：`requestId, expectedVersion, expectedSaveRevision` |
| 删除 | `POST adventure/saves/{saveId}/delete`：`requestId, expectedSaveRevision` |
| 重开 | `POST adventure/restart`：`requestId, expectedVersion` |

列表返回 `{entries, canSave, reason}`。每项包含 `id, name, revision, createdAt, sceneTitle, elapsedSeconds, version, kind, party`；`kind` 为 `manual` 或 `recovery`。写入返回 `{snapshot, saveId, replayed}`。

快照增加 `timelineId` 与 `lifecycle:{status,message,canAct}`。旧初始战役缺少 `timelineId` 时按空串处理；每次读取或重开生成新的值。不同时间线的快照版本可以降低，客户端不能仅比较 `version`。

所有战役变更请求携带当前 `X-DiceRealm-Timeline`，初始空值可省略。发送前与待确认请求一起冻结，原请求重试不得换成刷新后的值。旧分支的新写入返回 `409 campaign_timeline_changed`；存档控制的原回执独立保留，不随恢复回退。首次房号/邀请加入尚无快照，不要求时间线 header，仍在战役锁内校验当前凭证、容量与撤销；加入后的游戏写入正常校验时间线。
