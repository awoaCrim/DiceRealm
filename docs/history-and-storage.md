# 长期历史、回顾与存储

Unity「手记」提供逐页事件和事实回顾；浏览器工作台负责阅读副本导出与可恢复归档，二者位于「系统设置与 AI › 战役管理」（「导出系统日志副本」「归档为只读」），剧情回顾在「战役纪事与日志」。角色、世界、任务与旧叙事仍由服务端保存，不把客户端缓存当作权威存档。

---

### 在 Unity 中使用

Unity「手记」默认进入「历史原文」最近一页，页内按事件号从新到旧；每页最多 50 条，保留原输入、结果、检定、消耗与已获授权私密正文。旧页保持首次打开时的截止事件号，队友继续行动不会让正在阅读的页跳动；使用「回到最新」建立新的截止点。「冒险回顾」使用 `/recap` 的名称/地点/版本元数据和同一截止点的有界 `/activity` 故事记录，按新到旧展示原行动与已保存回应、更正和本人可读私密内容；不再展示任务/队员清单，不调用模型生成摘要，也不补写未经发生的故事。没有叙事的记录范围显示空态，仍可翻阅更早范围。任务、人物、地点、线索、势力和抉择归入「任务与人物」分类页；独立行动进展和同行伙伴页已移除。服务端 `/recap` 原事实字段和导出协议仍保留。

队长在浏览器工作台「系统设置与 AI › 战役管理」点「导出系统日志副本」导出完整历史，文件由浏览器下载到使用者选择的位置。格式为 UTF-8 JSON Lines：首行为公开快照与回顾，其后每行是一条按序号排列的事件。导出不包含访问凭证、凭证哈希、邀请秘密或重试回执。它是阅读副本，不能导入为可恢复存档。历史分页、回顾与导出都经 `ActionUnderstanding.ForViewer` 过滤：行动者的私密正文（`PrivateText`）只到行动者本人和主持，其他席位收到空串。正文仍可能包含玩家输入的私人内容，请谨慎分享。

「归档为只读」需要再次确认，且不能在战斗中执行。归档保留角色、世界、事件与原请求回执，阻止新行动、新加入、裁定和资源编辑；队长可恢复战役，也可继续撤销成员或未使用的邀请。旧的已接受请求仍可重放，不重新执行。先前已排队或已外发的生图不会因归档自动取消。

### 服务端存储

[CampaignStore](../server/DiceRealm.Server/Infrastructure/CampaignStore.cs) 使用每战役独立的 SQLite 数据库，保存紧凑状态、按序号索引的事件和按席位/请求 ID 索引的回执。普通行动只加载最近 100 条事件，旧回执按键查询，不再有早期的每战役 10000 次行动上限。原始判定及其骰点永久保留；没有通过清除旧回执缩小存档。

同一战役由进程内锁串行处理。模型调用发生在这个锁内，但不持有长时间 SQL 写事务。完成判定后，以短事务提交状态、新事件与回执，`synchronous=FULL`，提交成功才返回响应。约束失败会回滚全部写入。进程崩溃前尚未提交的随机样本仍不属于重放保证；外部供应商也不保证恰好一次计费。

数据目录仍只允许一个服务进程持有排他租约。使用 SQLite 不代表已支持多个服务副本或网络共享目录。JSON 资源任务和引用索引保留原有管线，供应商额度由同目录独立 SQLite 账本维护。

已有的 DiceRealm Unity 原型 JSON 存档在首次成功授权读取时导入。导入检查版本、战役 ID、连续事件和回执唯一性，先写完整临时数据库，再发布为正式数据库。原 JSON 文件逐字节保留，此后以 SQLite 为准；编辑原 JSON 不会覆盖新数据。导入失败保留原文件，不进行旧网页数据库迁移。

### 备份与恢复

先正常停止使用该数据目录的服务，再运行 备份脚本。脚本尝试取得同一个排他锁，服务仍在运行时会拒绝备份，不会终止进程。目标必须是源目录外尚不存在的 ZIP，不覆盖旧备份。

```powershell
./scripts/backup-data.ps1 -DataPath ./.local/playable-save -Destination ./artifacts/backups/playable-save.zip
```

备份包括战役数据库、保留的旧 JSON、资源任务、图片、参考图、视觉修订索引和额度账本。跳过运行锁与未发布的临时文件。备份含私人状态和凭证哈希，应按敏感数据保护；Unity 本机的会话、战役目录和待确认请求须另行保护，服务端备份不能找回丢失的明文访问凭证。

恢复时停止目标服务，把 ZIP 解压到新的空目录，再用 `-DataPath` 指向该目录。不要覆盖正在写入的数据，不要混合不同时间点的数据库和资源索引。保留原目录，验证战役和图片后再决定后续维护。恢复较旧备份会同时恢复较旧的本地额度计数，因此不能用它替代供应商账单或绕过运营限额。

### 协议与验证

[JournalService](../server/DiceRealm.Server/Application/JournalService.cs) 定义带截止点的分页、确定性回顾、归档命令与流式导出。详细字段见 [客户端协议](client-contract.md)。成员可以阅读共享历史与回顾；归档、恢复和导出要求队长权限。

[JournalTests](../tests/DiceRealm.Tests/JournalTests.cs) 验证超过早期容量上限的导入与重放、原文件保留、未授权不导入、索引查询、重启、事务回滚、无效旧存档、权限、冻结分页与导出不含凭证。浏览器冒烟脚本 验证实际工作台导出、确认归档与恢复；玩家端冒烟 验证手记阅读和跨端同步。引擎内测试覆盖真实 JsonUtility 的可空事件、命令持久重试和权限面板。

这一实现没有做多年运营规模的压力测试、物理断电/坏盘测试或在线备份调度。不要把正常重启和事务回滚测试当作这些验收的替代。
