# 剧本与提示词导入

DiceRealm 不提供默认剧本或默认系统提示词。主持人导入自己的内容，服务端负责校验、执行已支持的操作、掷骰与保存。创作文本不会自动成为可执行代码，也不能通过提示词绕过规则与权限。

---

### 从工作台导入

1. 启动服务端，打开同源的 `/workbench/` 页面，选择「创建新战役」，只填写战役名称（创建后只有主持席位，没有玩家角色）。Unity 不能创建战役，玩家通过房间号与共享密码加入，见 [入房](room-onboarding.md)。
2. 打开「剧本与提示词」，默认进入「输入式准备」。提供自己的原文、意图和独立整理提示词，明确确认后可得到有来源的草稿；查看缺口和依据，再采用。在「游玩提示词与版本」提供游玩原文，进入「检查、导入与试跑」。高级纠错和完整 JSON 导入继续保留。编辑、检查与导入不调用模型，只有明确确认的整理请求外发；非法导入整份拒绝。完整流程见 [输入式准备](input-preparation.md)。
3. 两份文档均已导入后，点击「检查完成，启用战役」。页面先检查绑定内容，并在确认框列出结构警告；确认后才设置起始场景、开放行动。启用不排队生图；地图需要在独立图册中另行保存和确认生成。
4. 需要下次重连工作台时，点击顶部「战役连接」并确认私有凭证警告，保存连接文件。该文件是主持连接，没有玩家角色，Unity 不能导入；玩家始终通过房间号与共享密码加入。

场景、地图、行动与任务来自本次导入，Unity 不另行生成剧情或判定结果。连接文件应私下保存，只用于下次连接同源工作台；它不是剧本包，不要分享或上传。

页面可以下载空白结构，也可以导出当前文档。空白结构没有示例剧情、文风或主持指令，必须填写才能使用。导入格式的编辑器辅助文件是 [剧本 JSON Schema](../schemas/adventure-v1.schema.json) 和 [提示词包 JSON Schema](../schemas/prompts-v1.schema.json)。最终以服务端 [ContentValidator](../server/DiceRealm.Server/Domain/ContentValidator.cs) 与 [PromptBundles](../server/DiceRealm.Server/Domain/PromptBundle.cs) 的校验为准，包括跨节点引用和重复标识检查。

JSON 文件采用 UTF-8。单次请求最大 1 MiB，包括请求包裹字段；系统拒绝未知字段、重复 JSON 字段和过深嵌套。不要把服务器路径、供应商密钥或访问凭证放进内容文件。服务端不会根据内容里的 URL 下载文件，也不会执行 JavaScript、C# 或表达式。

---

### 原文、表单与试跑

「高级剧本纠错」中的手动来源工具接收 UTF-8 的 TXT、MD 和 Markdown 文件，原文保存在 `sourceText`，包括文件中的 BOM 与 CR/LF 换行。Markdown 标题会列为可选片段；没有标题的文本列为一个片段。勾选并确认后，只把对应标题和原文复制到场景草稿，不自动推导路线、人物、检定或奖励。超过单场景长度的片段会拒绝复制，不截断原文。手工编辑来源文本时使用浏览器的换行格式。这只是高级纠错工具；输入式准备已支持有来源的受限整理，但仍不支持 PDF/Word 解析或任意规则自动生成。

路线图中的节点可用鼠标或键盘定位对应表单，出口方向以节点的出口列表为准。展开场景后可编辑条件、检定、后果、变体与受限遭遇；任务、人物、阵营和分支也通过表单填写。标识变更不会自动改写其他引用，编辑后要重新检查。表单结构直接来自项目的 [剧本 Schema](../schemas/adventure-v1.schema.json)，服务端仍执行最终校验。

创作草稿改为 IndexedDB 持久保存，按服务、战役和席位隔离；关页后重新用原连接进入同一浏览器可恢复，但浏览器清理数据或换设备不能保证恢复。请下载完整准备备份；双标签页冲突保留输入，明确载入而非自动覆盖。编辑或复制历史版本不会自动修改当前绑定。草稿可能包含未公开剧情，不要在公共浏览器中编辑，也不要把下载的内容与连接凭证混在一起。浏览器不能暂存时会提示立即导出。

在「检查、导入与试跑」运行静态检查。服务端报告首个结构或引用错误；通过后还会提示从起点结构上不可达的节点和含正向物品奖励的可重复行动、遭遇。可达性忽略条件，不证明每条条件分支都能完成，警告不会自动改写内容。任务奖励文字也不会单独发放奖励。

确认「用当前草稿创建隔离试跑」会建立独立战役，从草稿起点开始，使用战役中的玩家角色：无角色主持战役深拷贝首位队员的当前角色，旧的主持带角色战役按其模板与 build 重建一级新角色；没有任何角色时返回 `trial_character_required`，不复制正式资源、事实或进度，也不切换正式连接。试跑中的按钮仍由真实服务端规则结算。本页试跑的自由行动沿用旧 `/actions`，只进入待裁定，不测试模型理解质量；Unity 新主输入仍走 `/actions/input`。整个试跑永久禁止文本和图片模型调用，即使承载它的服务启用了供应商。试跑请求与行动可在响应丢失后重试，重启后保留离线标记。可归档结束试跑，或明确导出其私有连接；它不会成为正式战役的回滚或覆盖入口。

### 提示词包

| 字段 | 含义 |
|---|---|
| `formatVersion` | 固定为 `1`，表示数据格式版本 |
| `id`、`version`、`name` | 由你定义的包标识、修订标识与显示名称 |
| `intent` | 行动理解使用的系统提示词原文 |
| `narration` | 结果叙事使用的系统提示词原文 |

`intent` 和 `narration` 必填，各最多 32768 字符。支持普通 CR/LF 换行和制表符，拒绝其他控制字符。系统消息只包含相应导入字段的原文，不自动追加开发者设定的语言、故事、人物或文风；缺少提示词时不会偷偷回退到内置提示词。

模型接口仍有固定的机器协议。新主输入使用 `action|clarify|narrate|adjudicate` 及受限候选/非机械记忆合同，并原样发送 Intent 与 Narration 两段系统提示词；详见 [输入驱动冒险](input-driven-adventure.md)。旧意图接口的 `{"kind":"…","target":"…"}` 仅与已提供合法候选精确匹配时兼容，不能假设旧提示词可靠满足新合同。叙事结果必须是 `{"text": "…"}`，文本上限 4096 字符。服务端在请求数据中提供对应的输出契约，拒绝多余字段，叙事内容不被解析成 HP、资源或事实变更。模型可以输出数字或其他语言，但这些仍只是叙事，不能代替权威结果。

普通理解与叙事使用当前场景、有限公开信息、近期相关事件和权威结果，不发送完整 `sourceText`、内部 facts、完整角色/战役、主持秘密或尚未到达的知识。准备端点只在单独确认后外发本次明确提交的原文，不扩大普通游玩上下文。输入文本、名字和内容包均按数据处理，不获得调用工具或修改规则的权限。离线模式不伪造模型叙事，只展示已导入内容与服务端结果。

地图提示词在独立 [地图图册](maps.md) 中填写或导入，不附加系统题材。旧剧本的 `imagePrompt`、`styleProfile`、`visualConstraints` 和 `preGenerate` 仅保留兼容并原样导出，不再触发生图。

### 剧本包

完整字段定义见 [ContentModels](../server/DiceRealm.Server/Domain/ContentModels.cs)。字段名在 JSON 中使用 camelCase。

| 字段 | 用途 |
|---|---|
| `formatVersion`、`id`、`version`、`name` | 格式版本与内容版本标识 |
| `startSceneId` | 引用起始场景，不能指向不存在的节点 |
| `sourceText` | 你提供的背景或原始剧本文本，最多 200000 字符，保存来源，不自动进入普通游玩模型上下文 |
| `scenes` | 场景节点、出口、行动、条件、可选遭遇 |
| `items` | 自定义物品的 ID 和显示名称；不会创建未实现的装备数值规则 |
| `quests`、`npcs`、`factions`、`branches` | 任务、人物、关系与分支的条件化展示 |
| `initialKnowledge` | 可选非机械人物/任务/地点/线索，含 public/host/arrival 公开策略；见 [准备协议](input-preparation.md) |
| `level2Milestone` | 允许现有角色升至 2 级的条件；不填写就不开放此里程碑 |
| `styleProfile`、`visualConstraints` | 旧字段，只保存与导出，不再用于生成 |

`sourceText` 可由原文导入向导或 JSON 提供。输入式准备可把有依据的地点、明确路线和非机械知识整理为草稿，但不会自动产生地图坐标、检定、奖励或敌人。表单保存的执行格式仍是结构化 JSON，可执行部分需要由内容作者提供明确节点和操作。

#### 场景与路线

每个 `scenes[]` 节点有独立的 `id`、`title`、`summary`、`arrival`、`imagePrompt`。`x`、`y` 是 0 到 1 的旧探索图布局坐标；`unlocated:true` 明确没有位置依据，客户端忽略坐标，改用地点列表，不落针或绘制地理路线。输入式准备统一生成 unknown 位置；旧场景省略此字段仍保持原图。`safeRest: true` 标记允许常规休整、加入队伍和已满足条件的升级地点，不再绑定某个固定城镇。

`exits[]` 包含 `target`、`when` 和可选 `seconds`。目标必须存在，直接手写完整 JSON 时，省略时间仍按旧合同默认 600 秒，可配置为 0 到 86400 秒。输入式准备不会使用此默认值，有路线时必须由主持明确选择旅行秒数。客户端只得到当前合法出口；知道某个节点 ID 不等于能传送过去。

`variants[]` 按数组顺序匹配，第一个满足 `when` 的项替换标题与摘要。旧图片提示词仍随内容保存，但不执行；`preGenerate` 已停用，不再提供场景预生成候选。

#### 条件

条件统一使用 `all`、`any`、`none` 字符串数组：`all` 全部成立，非空 `any` 至少一个成立，`none` 全部不成立。空条件 `{}` 总是成立。条件既可以引用自定义事实，也可以使用 `visited:<场景ID>` 检查实际访问记录。

例如，`{"all":["your-fact"],"none":["other-fact"]}` 只是条件结构示意，其中的事实名称由你命名，不是平台剧情。系统不执行表达式或脚本。

#### 行动、检定与后果

`actions[]` 的 `id` 在整个包内唯一，`label` 是玩家看到的按钮文字。建议使用 `kind: "script.action"`，配合你定义的 `target`。也支持 `talk`、`investigate` 及 `story.*`、`script.*` 命名；不能覆盖 `combat.*`、`rest.*` 等规则动作。

每个行动可以有 `when`、`check`、`always`、`success`、`failure` 和 `repeatable`。默认只执行一次。`check` 声明属性、技能和 DC，骰点及角色加值由服务端计算；没有 `check` 时直接使用成功后果。`always` 在两种结果下都执行，然后执行对应的 `effects`。失败结果包含状态后果时，当前版本不会自动提供 Tactical Mind 改写窗口；需要主持人裁定，避免重复或矛盾地结算后果。

`effects[]` 只接受这些操作：

| `op` | 参数与语义 |
|---|---|
| `fact` | `key` 指定事实，添加一次；`amount` 为 0 |
| `removeFact` | 移除 `key` 指定事实；`amount` 为 0 |
| `item` | `key` 指定已声明或已支持的物品，`amount` 为增减数量；不足时行动不可执行 |
| `chapter` | `key` 留空，`amount` 为目标章号，只向前推进 |

物品操作针对队长角色的库存，当前没有通过剧本任意指定队员或批量修改角色的操作。剧情物品不会自动带有 AC、伤害或法术效果。不接受任意 HP、骰点、经验或法术位补丁。

#### 任务、人物和分支

任务通过 `visible`、`active`、`complete` 条件以及每个 objective 的 `complete` 条件投影到手记。注意空完成条件总为真，需要明确填写尚未完成时不成立的条件。人物有 `visible`、`met` 和按条件变化的 `locations`。阵营通过满足条件的 `adjustments` 求和；分支记录通过 `when` 决定是否可见。内容作者负责声明互斥条件，平台不自行决定剧情走向。

#### 遭遇

场景可配置一个 `encounter`，包含启动条件、标题、按钮文字、敌人资料、地形、启动后果与胜利后果。敌人的名字、数量和数值不再来自内置巡守。每次开战有独立实例 ID，按导入的定义恢复存档；击败全部敌人才执行胜利后果。

当前规则执行器仍有明确限制：7×5 棋盘、至多 4 名队员、1 到 3 个可见近战敌人，旧非致命模式必须声明 `nonlethal: true`；标准致命遭遇改为同时声明 `mode: "standard-2024"` 与 `nonlethal: false`，规则范围见 [标准战斗](standard-combat.md)。旧模式没有完整死亡豁免、敌方法术、隐匿或掩护自动化，导入不能解锁这些未实现规则。HP、AC、速度、攻击与伤害字段都有服务端范围校验；它们是剧本作者设置的遭遇资料，不自动被标注为官方怪物数据。

### 保存、权限与版本

剧本与提示词文档随战役一起保存，并记录 ID、版本和规范化 JSON 的 SHA-256。外部文件变化不会偷偷修改存档。启用前可重新导入剧本；启用后不能替换世界定义，换剧本请新建战役。提示词允许在战斗外明确导入新版本，不重置角色或剧情进度。每个战役保留最多 32 个不同的提示词版本，允许多个包标识；相同标识与版本不能覆盖不同原文，满库时拒绝继续增加，不自动删除历史。旧战役的当前提示词在首次管理时纳入历史，无法恢复系统升级前已经被替换的原文。

「游玩提示词与版本」可把保存版本复制到草稿、比较和导出，也可明确绑定回旧版本。比较器显示共同首尾之间的变更区间，并计入换行差异，不声称提供最小逐行差分。绑定只影响后续文本请求，历史事件不会重写。新行动事件的 `promptCalls` 记录行动理解与叙事各次调用的用途、包标识、版本、内容哈希及结果来源；工作台手记可展开查看。未调用模型的规则动作或离线试跑不产生伪造调用记录，升级前事件也不补造追踪信息。

完整文档的读取、导入和导出仅限队长。队员快照只有绑定摘要与当前可见世界信息，不包含完整剧本和系统提示词。剧本、提示词与阅读副本的导出不含战役凭证；但你写在内容中的私人文本会原样导出，应自行保管。「战役连接」是独立的敏感操作，明确确认后才下载席位凭证，不要混同两种文件。

导入使用与游戏行动一致的 `requestId`、`expectedVersion`、席位隔离和事务回执。网络中断后必须重发原请求，不重复应用内容。为支持刷新后的重试，未确认导入的原始请求暂存在本标签页的 sessionStorage 中，确认后删除；不要在不信任的公共浏览器中导入私人内容。

未绑定内容的旧开发存档不会被自动套用一个新剧本。服务端保留其角色和历史，以 `legacy_unbound` 标明状态；可以阅读和导出，但不能继续提交游戏行动。要使用可导入体系，应创建新战役。不要为了迁移而直接覆盖旧数据库。

### HTTP 接口

路径以 `/api/v1/campaigns/{id}` 为前缀，使用队长 Bearer 凭证。独立准备的 status / generate / receipt / inspect 端点及 IndexedDB 恢复合同见 [输入式准备](input-preparation.md)。

| 方法与路径 | 请求 | 返回 |
|---|---|---|
| `GET /content` | 无 | `{status, adventure, prompts}`，仅队长可读取完整文档 |
| `POST /content/adventure` | `{requestId, expectedVersion, document}` | `ActionResponse` |
| `POST /content/prompts` | `{requestId, expectedVersion, document}` | `ActionResponse` |
| `POST /content/activate` | `{requestId, expectedVersion}` | `ActionResponse` |
| `GET /content/prompt-history` | 无 | `PromptRevision[]`，包含保存原文，仅队长可读 |
| `POST /content/prompts-bind` | `{requestId, expectedVersion, hash}` | `ActionResponse`，绑定当前战役已保存的版本 |
| `POST /content/preflight` | `{document, prompts?}` | `{valid, issues}`，不写入或调用模型 |
| `POST /content/trial` | `{requestId, expectedVersion, accessToken, document, prompts}` | `{trial: {accessToken, snapshot}}`，独立试跑，不修改原战役 |

`POST /api/v1/campaigns` 默认创建空白战役。程序化调用也可以显式传入 `adventure`、`prompts` 和 `startImmediately: true`，校验通过后直接启用；系统仍没有默认内容。

试跑的 `accessToken` 是客户端安全随机生成的独立 64 位十六进制凭证，必须随原请求保存后再发送；服务端持久化哈希，不把它写入正式快照。试跑编号由源战役和请求编号派生，同一内容重试会返回同一个试跑的当前状态。普通创建接口不能把既有战役改成或改出试跑。

无效文档返回 `invalid_content` 或 `invalid_prompts`；未完成导入返回 `content_required`；试图替换已开始的剧本返回 `content_locked`；版本和幂等冲突沿用 `stale_version`、`idempotency_conflict`。失败不写入部分剧情，也不回退到其他剧本。

提示词同版本原文冲突返回 `prompt_version_conflict`，版本库已满返回 `prompt_library_full`，未知保存版本返回 `prompt_revision_missing`；试跑生图返回 `trial_provider_disabled`。
