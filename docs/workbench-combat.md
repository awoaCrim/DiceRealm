# 在工作台查看战斗

打开战役的「剧情」页。开始确认先攻或进入战斗后，正文上方会出现战况条，显示战斗名称、回合、当前行动者和等待事项。选择「查看战况」打开详细窗口；没有战斗或开战等待时不占用正文空间。

## 先看轮到谁，再查单位详情

「战况」按服务端的先攻顺序列出参战者，显示生命／临时生命、护甲等级、状态，以及移动、动作、附赠动作和反应的剩余情况。选择单位可看已记录的死亡豁免、稳定、专注、法术位和资源；有持久棋盘实例的NPC详情从同一实例读取。

战术格位图对应当前战斗的格子、地形和单位位置，编号与先攻列表一致。它用于查阅，不能拖动单位或执行行动；不是场景插画，也不替代玩家端的地图。

主持人可以看到队员分别等待什么，以及已经确认、上下文已变化或无法继续的原因。开战前全员尚未确认时，也能查看各人的先攻等待。Shield、死亡豁免、专注等等待保留服务端说明。阅读和关闭窗口都不会替玩家回应、掷骰或推进游戏。

## 战报不必等AI叙事

已结算的移动、攻击、伤害、法术和检定直接显示在剧情里，即使该步没有AI叙事也不会遗漏。「战报」页签按回合和记录顺序阅读近期记录，选择条目查看已保存的攻击骰、修正、命中、伤害与检定结果。未记录的DC或数值不作推算。

当前战斗只保留最近200条战报；更早记录仍可从剧情的历史分页读取。战斗结束后显示实际结果，保留最后状态与记录。读档、重开或新一场战斗会切换到对应进度，不混用旧战斗的选择和记录。

轮询更新保留仍有效的页签、单位选择与阅读位置。读取失败时显示重试入口；重试只重新读取，不会重发行动。

## 主持只读接口

`GET /api/v1/campaigns/{id}/combat/overview` 使用原战役鉴权，仅主持可读；无角色主持同样适用。响应为：

```text
{ campaignId, timelineId, version, combat, waits }
waits[] = { id, actorId, actorName, kind, label, description, state, reason }
```

`combat` 为现有主持战斗投影或 `null`；`kind` 为 `roll` 或 `intent`，`state` 为 `pending`、`confirmed`、`stale` 或 `blocked`。等待项仅包含当前合法席位的相关未完成请求，不含可执行命令、候选载荷或模型请求。未开战时只列明确的战斗操作；活动战斗中列参战席位的等待。

单位详情复用 `GET /api/v1/campaigns/{id}/board/tokens/{entityId}`。两个读取都不改游戏版本、不掷骰、不调用模型。普通玩家无法读取主持概览，仍只消费原快照与历史中已授权的战斗信息；隐藏敌人与私有历史继续由服务端过滤。
