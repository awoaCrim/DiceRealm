# 完整角色成长

本页描述当前源码的完整 `build` 成长流程。旧预设及受限 `creation` 的二级升级继续由 [原成长流程](characters-and-growth.md#灯塔里程碑) 处理，不转换其历史或请求回执。

## 玩家流程

网页 `/play/` 在角色窗「成长」页，Unity 在角色窗口点“升级与成长 →”（工作台不再提供成长页）。读取成长机会，选择本次提升的职业，更新预览并补齐服务端返回的子职业、专长、法术等选择，最后确认这一级。每次只提升一级，总等级至多 20；资格来自已记录经验、明确里程碑或已启用剧本的二级条件，不能靠描述“我升级了”取得等级。

预览不升级、不掷骰、不恢复资源，也不调用模型。当前角色未审核、存在待投掷/待处理意图、正在战斗、地点不能安全休整或尚未获资格时不能确认。服务端重新校验条件；隐藏按钮不构成权限边界。

草稿固定战役版本。轮询或关闭窗口不会自动改版；版本变化时保留旧选择，只能明确放弃后重新读取。修改选择会废弃旧预览。未发送选择只在当前客户端会话内保存；工作台按连接席位隔离。已经发送但结果未知的请求另外持久化，重试使用原端点、原 UUID、原版本和原正文。不能通过生成新 UUID 或套用最新版本重复升级。

成长保留原始一级 Build、人物身份、装备、伤势、临时生命及已有消耗，追加逐级取得记录。提高上限只增加新容量，不补回已花费量；0 HP 不因升级自动醒来。多职业按各职业等级计算取得条件，不因总等级或共享法术位提前取得高环法术，也不领取第二份初始装备或完整初始豁免熟练。

## 成长后的准备与休整

角色卡按职业分别提供准备清单、法术书和施法来源。长休后，支持重新准备的每个职业各有自己的调整窗口；切换未发送的准备草稿有明确提示。窗口中的确认携带职业 ID，不能把主要职业清单写到另一职业。能力来源、施法属性、资源与具体法术位路线由服务器提供。

相同面数的生命骰合池，不同面数分别选择。短休先经过一小时，可明确选择一颗 d6/d8/d10/d12 中本人拥有且尚未花费的骰；同次短休之后逐颗追加，不再推进一小时。含生命骰的行动仍须本人明确同意才掷骰、扣骰、治疗，查看和取消不产生效果。旧主要职业的空 target / `hit_die` 请求保持语义。

完整成长角色的奥术回想按**法师职业等级的一半向上取整**提供已花费法术位组合，单次最多使用该额度，不恢复六环以上法术位，也不把契约法术位纳入组合。需要持有法术书且尚有本次长休间的使用次数；玩家明确选择组合后消耗一次。契约位按其独立短休规则恢复。恢复后仍可在同次短休追加生命骰。

长休窗口还支持四种本人来源重选：高等精灵替换一个血统戏法；法师法术精通从当前法术书中替换两个精通法术中的**一个**同环动作法术；大地结社切换当前地貌及对应职业等级法术；能量抗性恩惠重选两种抗性。只调整该来源，保留其他来源的同名法术／抗性、原 Build、取得历史和已有消耗。每个来源每次长休只确认一次，可与逐职业准备以任意顺序完成；其他行动关闭余下窗口。

工作台成长页直接显示这些服务端选项。主输入也可提议确切来源选项，但仍须本人明确确认，不由模型自动替玩家决定。休息选择走既有 `character/commands` 的 `operation=rest-choice`，`target` 为公开来源 key，`choices` 为选中 ID；不用新增任意状态写接口。

## HTTP 与持久化

端点均位于 `/api/v1/campaigns/{id}`，以 bearer 凭证确定席位：

| 端点 | 请求 | 权限与结果 |
|---|---|---|
| `GET character/advancement` | 无正文 | 本人只读机会、职业选择；`preview` 可为 null |
| `POST character/advancement/preview` | `expectedVersion, draft` | 本人已审核；返回只读选择组、问题与可能的角色预览 |
| `POST character/advancement/apply` | `requestId, expectedVersion, draft` | 本人逐级提交；返回 `ActionResponse`，resolution.kind 为 `growth.apply` |
| `POST characters/advancement/award` | `requestId, expectedVersion, actorId, kind, value, rationale` | 仅主持，且接收者须为已接纳角色；授予资格，不直接升级 |

`draft` 只含 `revision, classId, subclassId, selections`，其中 selections 为 `{key, values[]}`。客户端只选择公开 group/options 中的值，不传 HP、最大资源、豁免 DC 或其他派生结果。preview/apply 正文上限 64 KiB，award 上限 8 KiB。经验奖励为正数，累计不超过 355000；里程碑值须高于当前及已获等级、不超过 20，并有非空依据。

`Character.Advancement` 是可空追加状态（schemaVersion=1），包含各职业当前记录及连续的二级至当前级取得步骤；`Campaign.AdvancementAwards` 是可空依据记录。旧存档没有这些字段时保持原流程；已有高等级 Build 缺失取得历史时拒绝猜测。未来 schema 或坏记录不得当成空状态覆盖。

apply 的身份校验早于回执查找；原席位回执早于可变版本/归档等检查。同一 UUID 的同一正文只提交一次，同一席位改正文冲突；不同席位的 UUID 空间隔离，撤权后不能靠旧回执绕过鉴权。回放返回当前快照及原 resolution，因此快照可能比当初的下一等级/下一版本更晚，客户端不能要求恰好 `expectedVersion + 1`。Unity 只接受匹配战役、角色、命令及完整成长状态的成功体；无效 2xx 仍保留原请求。

过期版本为 `stale_version`，ID 复用为 `idempotency_conflict`，未获资格/地点或等待状态为 `advancement_unavailable`（待投掷还可能返回 `roll_pending`），未完成选择为 `advancement_incomplete`。返回明确拒绝后可根据当前状态重新选择；网络失败、5xx 或不完整成功体表示结果未知，只能原样重试。

## 实际覆盖与未完成边界

源编译目录来自固定本地 XPHB 数据，包含 12 职业、48 子职业、77 专长、58 可选能力与 391 法术的成长元数据。编译器校验 manifest、各输入和书籍证据的固定哈希；缺证据拒绝，不联网补源或改用旧版。`python -O` 不能关闭这些检查。规则书名、页码、特性 UID 和数据修订保留在后端，不展示在普通成长表单中。

已实现逐级路径、主要属性兼职前提、职业独立法术资格、共享/契约位分离、固定 HP 和 CON 追补，以及已接入的训练/被动派生。例如 Skilled 实际取得新的技能/工具组合；能量抗性恩惠的所选抗性进入角色派生；重复 Magic Initiate 必须选择不同列表，新增一级法术同时提供其免费次数与已有法术位路线。已取得的法术来源列表不能在升级中偷偷切换并混合两份列表。

Magic Initiate 的每份取得来源现在可在任意职业升级时更换一个法术：戏法只能换同列表戏法，一级法术只能换同列表一级法术；不更改来源施法属性或列表。默认保留，修改不会移除其他来源持有的同名法术，也不会补回已用免费次数。原始一级 Build 不变，替换选择追加在本次成长步骤中。精灵与提夫林的六种血统按**人物总等级** 3／5 授予原血统的固定法术，并保留建卡施法属性；免费与合适法术位路线均可用。森林侏儒使用次数按熟练加值成长；Ranger 的 Favored Enemy 次数按游侠职业等级表成长，兼职不会误用总等级或熟练加值。

一级来源已接通成长交接：Cleric Thaumaturge / Druid Magician 的额外戏法并入当前职业清单，支持后续合法替换，不再重复授予；初始 Warlock 祈唤被替换后移除旧来源法术和能力标签。Armor of Shadows 保留只对自己无槽施放 Mage Armor，Pact of the Chain 保留 Magic 动作无槽 Find Familiar；没有免除材料或自动召唤魔宠。

Agonizing Blast、Eldritch Spear、Repelling Blast 可以分别多次取得，每份绑定不同的合格 Warlock 戏法并占一个祈唤名额。更换戏法须同时保持绑定资格，Spear 排除接触／自身／小于10尺范围，Repelling 需要攻击掷骰；一次升级最多替换一个旧祈唤实例。旧单绑定记录兼容读取，明确升级才转换当前身份，不改旧取得步骤。

Lessons of the First Ones 支持当前完整目录中的 10 种 Origin 专长，每份祈唤必须选择不同专长。专长的技能、工具、武器熟练及常驻派生按来源记录；撤销后保留其他来源提供的同名训练。Skilled 提供的技能消失时，对应独立专精暂不生效，重新获得该熟练可恢复；Tough 的失去按当前总等级扣回对应生命上限，保留伤势，可能使本次升级生命值净变化为负，不能产生负 HP 或唤醒 0 HP 角色。

Magic Initiate 复用现有列表／属性／法术选择、免费与法术位路线及升级时换一个法术的流程。Lucky 或免费法术来源被撤销后，不在当前资源／施法清单中残留；重新取得同一来源的消耗按**本项目的同周期保留策略**处理：同一次长休周期不刷新，确实完成新的长休后才恢复。该规则避免借反复来源替换补回次数，不把它冒称为原文针对“重新取得”的独立条款。

秘法奥秘在 Warlock 职业等级 11／13／15／17 取得六／七／八／九环来源。以后每次 **Warlock 职业升级** 可选择替换已有来源中的一个法术，只能换另一同环 Warlock 法术；升级其他职业不开放。新环级取得与一个旧来源替换可以同次进行。来源的长休一次无槽施法次数保持已花费量，不因改法术刷新；默认保留，原 Build 和旧步骤不改写。

**取得能力不代表主动效果已自动结算。** 当前高级成长投影仍关闭旧受限战斗引擎的自动资格，后续战斗主线负责实际动作/反应/效果。已经接入的成长机制仍不等于全部主动能力语义，不应把 48 条等级路径通过当作完整 D&D 自动执行。
