# DM 后台工作台前端重设计 PRD

## 1. 背景

当前管理页已经承载了房间管理、AI provider、Prompt 配置、剧本/世界书、数据库插件、战役记忆、角色资源、AI 回合处理等大量能力，但信息架构仍然接近“功能堆叠”。DM 很难判断：

- 剧本、世界书、数据库、战役记忆分别有什么用。
- Prompt 配置会影响什么。
- 本轮 AI 到底参考了哪些资料。
- 哪些内容是玩家可见，哪些只是 DM 或 AI 可见。

本轮重设计的核心不是新增能力，而是把现有和规划中的能力重排成一个清楚的 **DM 主持工作台**。

## 2. 产品决策

### 2.1 数据库与世界书的关系

前端不再把“世界书”作为独立顶级系统。

采用：

> 战役数据库 = 结构化资料 + 世界书式 AI 注入规则 + AI 更新审计。

含义：

- 数据库负责保存资料。
- 世界书能力变成每条资料的“AI 参考规则”。
- AI 请求预览展示本轮命中的数据库资料。

用户不需要同时理解“数据库”和“世界书”两个入口。用户只需要知道：资料放进战役数据库，勾选或配置“AI 参考规则”，它就会在合适时机进入 AI 上下文。

### 2.2 Prompt 配置的定位

`Prompt 配置` 改为 `AI 主持风格`。

它不负责保存世界资料，也不负责导入剧本。它只回答：

- AI 用什么叙事风格。
- 公开/客观/私人剧情分别用什么人称。
- 每轮剧情长度是多少。
- AI 输出 JSON 契约和规则约束是什么。
- 当前启用哪个主持预设包。

### 2.3 剧本的定位

剧本是战役的起点和结构，不等于世界书。

剧本进入 `战役设置` 或 `内容来源`，用于定义：

- 冒险名称。
- 开场地点。
- Opening Scene。
- 初始 NPC、地点、任务、线索。
- 初始战役数据库种子。

## 3. 目标

### 3.1 用户目标

DM 应该可以在 30 秒内理解：

- 现在房间处于什么状态。
- 玩家是否到齐、角色是否确认、是否能开场。
- 当前剧情推进到哪里。
- AI 本轮会参考哪些资料。
- 去哪里改 AI 风格，去哪里改世界资料。

### 3.2 业务目标

- 降低管理页认知负担。
- 让战役数据库成为唯一资料入口。
- 让 AI 请求预览从“调试文本框”变成 DM 可理解的上下文说明。
- 保留高级调试能力，但默认折叠。

## 4. 非目标

本轮 PRD 不要求：

- 重做后端 schema。
- 删除旧原生世界书数据。
- 一次性实现完整结构化数据库引擎。
- 引入大型 UI 组件库。
- 做移动端专项设计。
- 做华丽营销页或沉浸式插画。

## 5. 导航结构

### 5.1 新顶级导航

建议管理页主导航调整为：

1. `总览`
2. `跑团`
3. `战役数据库`
4. `AI 主持`
5. `玩家与角色`
6. `设置`

### 5.2 旧入口映射

| 当前入口 | 新位置 | 处理 |
|---|---|---|
| 总览 | 总览 | 保留并强化状态摘要 |
| AI 接口 | 设置 > AI 接口 | 降级为设置项 |
| Prompt 配置 | AI 主持 | 改名并重排 |
| 剧本/世界书 | 战役数据库 / 设置 > 内容导入 | 拆分语义 |
| 数据库插件 | 战役数据库 > 数据源 | 合并 |
| 战役记忆 | 战役数据库 > 纪要 / 记忆 | 合并 |
| 角色资源 | 玩家与角色 > 资源变动 | 合并 |
| 世界书 | 战役数据库 > AI 参考规则 | 不再作为顶级入口 |

## 6. 页面设计

## 6.1 总览

总览是 DM 打开房间后的默认页。

### 内容区块

1. 房间状态条
   - 房间名
   - 当前回合
   - 房间状态
   - 预期玩家数
   - 已加入玩家数
   - 已确认角色数

2. 开场准备状态
   - 玩家是否到齐
   - 角色是否全部确认
   - NPC 是否已自动补齐
   - 个人开场是否已生成
   - AI provider 是否可用

3. 本轮行动概览
   - 每位玩家的行动状态
   - 四个建议行动是否已生成
   - 可跳过玩家
   - 可进入 AI 回合预览

4. 最近剧情
   - 最新公开剧情
   - 最新客观剧情摘要
   - 最近私人更新数量

### 设计要求

- 总览不要展示完整 Prompt。
- 总览只给“现在该做什么”的行动入口。
- 使用紧凑状态 chip：`已就绪`、`缺角色`、`等待玩家`、`AI 异常`。

## 6.2 跑团

跑团页是 DM 每回合实际操作的主工作区。

### 布局

三栏布局：

- 左栏：玩家行动队列。
- 中栏：AI 回合生成与预览。
- 右栏：本轮 AI 上下文摘要。

### 左栏：玩家行动队列

每位玩家一张紧凑行：

- 玩家名
- 角色名
- 当前状态：等待行动 / 已提交 / 已跳过
- 本轮提交内容
- DM 操作：跳过、查看角色、查看私人剧情

### 中栏：AI 回合处理

流程按钮：

1. `生成本轮提示词`
2. `发送给 AI`
3. `检查结果`
4. `应用剧情与状态`

如果 AI 失败：

- 保留当前提示词。
- 显示 `重新发送`。
- 显示 `重新生成提示词`。
- 显示 `放弃本次结果`。

### 右栏：AI 上下文摘要

默认展示人类可读摘要：

- 当前场景
- 最近公开剧情摘要
- 命中的战役数据库资料
- 使用的规则摘要
- 私人信息数量
- 本轮输出要求

底部可展开：

- 原始 prompt
- JSON 输出契约
- 数据库命中明细

## 6.3 战役数据库

这是新前端的核心资料入口。

### 6.3.1 页面结构

左侧为表/分类导航：

- `全部`
- `世界设定`
- `NPC`
- `地点`
- `任务`
- `线索`
- `物品`
- `纪要`
- `数据源`

中间为记录列表。

右侧为记录详情编辑器。

### 6.3.2 记录列表

每条记录展示：

- 标题
- 类型
- 可见性：DM / 公开 / 私人
- AI 参考状态：常驻 / 关键词 / 不参考
- AI 更新状态：允许 / 需审核 / 禁止
- 最近更新时间

列表顶部提供：

- 搜索
- 类型筛选
- AI 参考筛选
- 可见性筛选
- 新建记录

### 6.3.3 记录详情

详情分区：

1. 基础资料
   - 标题
   - 类型
   - 简介
   - 正文
   - 标签

2. 可见性
   - 仅 DM
   - 公开
   - 指定玩家私人可见

3. AI 参考规则
   - 不给 AI
   - 总是参考
   - 提到关键词时参考
   - 关键词列表
   - 优先级
   - 最大注入长度

4. AI 更新规则
   - 禁止 AI 更新
   - AI 可建议，需 DM 审核
   - AI 可自动更新非关键字段
   - 可更新字段列表

5. 变更历史
   - 最近 AI 建议
   - DM 应用/拒绝记录

### 6.3.4 数据源

数据源页合并现有“数据库插件”和资源导入功能。

展示：

- 已导入来源 URL
- 类型
- 版本
- hash
- 上次检查时间
- 更新状态

操作：

- 导入 URL
- 检查更新
- 应用更新
- 删除来源
- 查看导入表

### 6.3.5 世界书兼容

旧原生世界书不直接删除。

迁移策略：

- 在 `数据源` 或 `高级` 区显示“旧世界书条目”。
- 每条旧世界书可转换为数据库记录。
- 转换后：
  - `title` -> 记录标题
  - `content` -> 正文
  - `keys` -> AI 参考关键词
  - `constant` -> 总是参考
  - `priority` -> 优先级

## 6.4 AI 主持

AI 主持页替代当前 `Prompt 配置`。

### 内容结构

1. 当前主持模式
   - 当前启用预设包
   - 叙事风格摘要
   - 输出语言
   - 公开剧情人称：第三人称
   - 客观剧情人称：第三人称
   - 私人剧情人称：第二人称

2. 剧情长度
   - 开场剧情长度
   - 公开剧情长度
   - 私人剧情长度
   - 客观剧情长度
   - 骰点后重写长度

3. 输出规则
   - 不替玩家决定未来行动
   - 不提前泄露隐藏信息
   - 公开/私人/客观日志边界
   - 投掷结果如何写入剧情

4. 预设包
   - 当前生效预设
   - 可切换模板
   - 预设块摘要

5. 高级 Prompt 编辑
   - 默认折叠。
   - 展开后显示旧原生预设模板。
   - 适合开发/高级 DM，不作为普通主流程。

### 设计要求

- 页面顶部不要直接出现 raw prompt。
- 先给 DM 看“当前 AI 会怎么主持”。
- raw prompt 放到 `调试预览` 抽屉。

## 6.5 玩家与角色

合并玩家管理、角色卡、角色资源变动。

### 内容结构

1. 玩家列表
   - 玩家名
   - 角色确认状态
   - 链接复制
   - 私人剧情入口

2. 角色卡摘要
   - 每名角色一张卡
   - HP / AC / 职业 / 种族 / 背景
   - 熟练、语言、豁免、技能入口

3. 资源变动
   - HP
   - 法术位
   - 弹药
   - 状态
   - 待审核变动

4. NPC 自动补位
   - 预期玩家数不足 4 人时显示系统 NPC 状态。
   - 可查看 NPC 简介。
   - 不把 NPC 当成真实玩家链接。

## 6.6 设置

设置页收纳低频配置。

### 子区块

- AI 接口
- Embedding 接口
- 房间设置
- 导入/导出
- 高级调试

### 设计要求

- AI provider 的 key、base URL、model 都放这里。
- 不在跑团页展示 provider 表单。
- provider 异常在总览和跑团页只显示状态和修复入口。

## 7. 视觉设计方向

### 7.1 气质

关键词：

- 暗色
- 克制
- 信息密度高
- DM 工具感
- 少量奇幻质感

避免：

- 大面积装饰渐变
- 营销式 hero
- 太多浮夸卡片
- 每个区块都像一张独立大卡
- 紫蓝单色调过重

### 7.2 布局

桌面优先。

推荐结构：

```text
------------------------------------------------+
| 顶部房间状态栏                                  |
+----------+----------------------+--------------+
| 导航     | 主工作区              | 上下文侧栏   |
|          |                      |              |
|          |                      |              |
+----------+----------------------+--------------+
```

### 7.3 色彩

建议：

- 背景：近黑灰，而不是纯黑。
- 主边框：低对比灰绿或灰金。
- 强调色：旧金色，用于主要操作和命中项。
- 信息色：青绿色，用于 AI 参考、数据库命中。
- 危险色：暗红，用于失败、阻塞、AI 错误。

### 7.4 组件规范

- 顶级导航使用左侧列表，而不是横向挤压 tab。
- 状态用 chip。
- 记录列表用密集 table/list。
- 详情编辑用分区面板。
- Raw prompt 用抽屉或折叠区。
- 高级功能默认折叠。
- 主按钮只保留一个明确下一步。

## 8. 文案原则

### 8.1 少用技术词

替换：

| 旧词 | 新词 |
|---|---|
| Prompt 配置 | AI 主持 |
| 世界书 | AI 参考规则 / 世界设定 |
| 数据库插件 | 战役数据库 |
| 资源配置 | 内容来源 |
| 最终 prompt | 本轮 AI 请求 |
| 运行时槽位 | 本轮上下文 |
| 旧原生预设 | 高级模板 |

### 8.2 每个页面只回答一个问题

- 总览：现在该做什么？
- 跑团：如何处理本回合？
- 战役数据库：资料在哪里，AI 什么时候参考？
- AI 主持：AI 应该怎么写、怎么裁定？
- 玩家与角色：玩家和角色现在怎样？
- 设置：系统怎么连接和运行？

## 9. AI 请求预览设计

AI 请求预览应分两层。

### 9.1 默认摘要

显示：

- 本轮目标
- 当前场景
- 玩家行动
- 命中的数据库资料
- 使用的规则
- 私人信息数量
- 输出要求

命中的数据库资料应显示原因：

```text
黑松林
命中原因：玩家行动提到“北方密林”
注入方式：关键词
优先级：高
```

### 9.2 高级详情

折叠显示：

- 完整 prompt
- Prompt blocks
- JSON output contract
- 原始上下文槽位
- 数据库 raw rows

## 10. 空状态

### 战役数据库为空

文案：

> 还没有战役资料。你可以从剧本导入初始资料，也可以手动创建 NPC、地点、任务或线索。

按钮：

- `从剧本导入`
- `新建资料`
- `导入数据库 URL`

### AI 主持未配置

文案：

> 当前使用默认主持风格。你可以调整叙事长度、人称和输出规则。

按钮：

- `选择预设`
- `预览本轮 AI 请求`

### AI provider 异常

文案：

> AI 接口不可用，无法生成剧情。已保留当前提示词，可以修复接口后重新发送。

按钮：

- `去设置`
- `重新发送`

## 11. 交互细节

### 11.1 重新生成 / 重新应用

AI 应用失败后必须保留：

- 当前 preview
- AI 原始结果
- 已解析变更
- 错误原因

提供：

- `重新应用`
- `重新生成`
- `编辑后应用`
- `放弃`

### 11.2 AI 建议变更

数据库、资源、状态变更都进入统一审核列表：

- 变更对象
- 原值
- 新值
- 理由
- 来源：AI / DM / 玩家
- 操作：应用 / 拒绝 / 编辑

### 11.3 本轮四个选项

玩家端每轮开始展示四个建议行动。

DM 后台应能看到：

- 是否已生成。
- 每名玩家看到的选项。
- 是否允许玩家自定义输入。

## 12. 实施优先级

### P0：信息架构改名与合并

- 顶级导航重排。
- `Prompt 配置` 改为 `AI 主持`。
- `数据库插件` 改为 `战役数据库`。
- 隐藏独立 `世界书` 顶级入口。
- 把原世界书配置移入战役数据库高级区。

### P1：战役数据库页面

- 表/分类导航。
- 记录列表。
- 记录详情。
- AI 参考规则 UI。
- 数据源列表。

### P2：AI 请求预览升级

- 默认摘要。
- 命中资料原因。
- 高级 raw prompt 折叠。

### P3：跑团工作台

- 玩家行动队列。
- AI 回合流程按钮。
- 上下文侧栏。
- 错误后重新生成/重新应用。

### P4：视觉 polish

- 左侧导航。
- 状态 chip。
- 密集列表。
- 暗色主题细化。
- 高亮命中资料和投掷结果。

## 13. 测试要求

客户端测试：

- 管理页显示新导航：`总览`、`跑团`、`战役数据库`、`AI 主持`、`玩家与角色`、`设置`。
- 不再出现顶级 `世界书` tab。
- `AI 主持` 页面显示叙事长度、人称规则、当前预设。
- `战役数据库` 页面显示资料类型和 AI 参考规则。
- AI 请求预览默认显示摘要，不直接展开完整 prompt。
- Provider 错误后显示重新发送/重新生成入口。

手工验证：

- 创建房间。
- 添加玩家。
- 确认角色。
- 进入总览看开场准备状态。
- 进入跑团页生成 AI 回合。
- 进入战役数据库查看命中资料。
- 进入 AI 主持调整长度和人称规则。

## 14. 成功标准

- DM 不需要知道 SillyTavern 世界书术语，也能配置 AI 参考资料。
- 数据库、世界书、剧本、Prompt 的边界在 UI 上清楚。
- 跑团主流程不需要进入高级配置页。
- AI 请求预览能解释“为什么本轮 AI 知道这些资料”。
- 高级调试能力仍保留，但不会干扰普通使用。
