# 工作台账户与用户战役

## 使用

打开同一服务的 `/workbench/`，先登录，再从“我的战役”选择“继续战役”。不再上传连接文件或填写战役凭证。创建战役只填名称，战役与当前账户归属一起保存；剧本和叙事仍在创建后设置。

首次使用新数据目录时创建唯一的 `admin`。初始密码取自配置 `Accounts:InitialAdminPassword`（环境变量 `Accounts__InitialAdminPassword`，8–128 字符）；没有配置时随机生成，并只在服务启动日志中显示这一次。源码不含任何默认密码或其散列。已有账户文件的数据目录忽略此配置。管理员可在顶栏账户菜单的“修改密码”更新自己的密码，重启不会恢复初始密码。普通账户由管理员创建，没有开放注册。

顶栏以用户名打开账户菜单，统一提供“我的战役”“修改密码”“退出登录”；管理员额外拥有“用户管理”。不再保留重复的“战役连接”面板。

管理员“用户管理”支持创建账户、查看用户战役、停用/恢复和重置密码。停用不删除角色、战役或历史；停用、重置密码和本人改密撤销该用户所有登录会话。不能停用唯一管理员；管理员本人改密需要当前密码。普通用户只看到自己创建的战役，管理员能查看和操作全部战役。

升级前的战役没有账户归属，保留原数据，在管理员列表标为“旧战役（未关联账户）”。不会根据连接文件或浏览器缓存猜测归属。旧 Unity 主持/队员凭证仍按原席位权限使用，不会因为新增网页账户而失效。

## 接口

全部位于 `/api/v1/accounts`，除登录外使用 `Authorization: Bearer <账户会话>`。用户投影只有 `{id,username,isAdmin,disabled}`；不会返回密码哈希、盐或永久主持凭证。

| 方法与路径 | 请求 | 响应 |
|---|---|---|
| POST `/login` | `{username,password}` | `{accessToken,user}` |
| GET `/me` | 无 | 用户投影 |
| POST `/logout` | 无正文 | `{ok:true}` |
| POST `/password` | `{currentPassword,password}` | `{ok:true}`，随后重新登录 |
| GET `/campaigns` | 无 | `{campaigns:[{id,name,archived,ownerUserId,ownerUsername,unavailable}]}` |
| POST `/campaigns` | `{name}` | 201 `{campaignId}` |
| GET `/users` | 无，仅管理员 | `{users:[用户投影]}` |
| POST `/users` | `{username,password}`，仅管理员 | 用户投影 |
| POST `/users/{id}/status` | `{disabled}`，仅管理员 | 用户投影 |
| POST `/users/{id}/password` | `{password}`，仅管理员 | `{ok:true}` |

用户名 1–40 个字母、数字、点、短横线或下划线，大小写不区分；密码 8–128 个字符，不允许全空白或控制字符。未知字段拒绝。登录沿用现有限流框架，按网络来源每分钟 20 次、全服务每分钟 120 次；不使用转发头猜来源。

全局 AI 配置继续要求本机地址、同源及固定自动请求头，并额外要求管理员账户；战役主持身份不足以修改全局供应商密钥。不增加独立解锁或二次确认。

## 存储与恢复

`AccountStore` 在数据目录的 `accounts.json` 原子保存 schemaVersion 1、账户、会话哈希和房间指纹密钥。密码使用 PBKDF2-SHA256 / 600000 次 / 16 字节盐 / 32 字节哈希；随机会话仅保存哈希，有效期 30 天。坏记录或未知版本拒绝使用并保留原文件，不能重建空库覆盖。

战役 `OwnerUserId` 与战役初次保存同次提交；旧档缺省 null。列表在各战役锁内只读摘要，不推进版本，不迁移旧 JSON，不改归属。账户鉴权最终仍在 `CampaignStore.Access` 的锁内执行，列表和前端控件不是权限边界。

单个战役损坏、格式不支持或不可读时，不阻断其他战役。管理员列表显示“无法读取的战役”、文件标识和“损坏或不支持”，`unavailable=true`，不提供继续入口，原文件不动；正常记录省略`unavailable`（缺省为false）。无法验证坏记录归属时不向普通用户展示。已有SQLite不会因损坏而回退同名旧JSON；账户库、整个目录的读取错误或请求取消仍正常报错。

浏览器登录只保存在当前标签页的 `sessionStorage`，不保存密码；关掉标签页后重新登录即可重新拉取战役。服务端重启保留有效会话。账户战役的未确认请求按“服务地址 + 战役 + 用户 ID”隔离，不随登录 token 轮换而遗失；401 不清掉可能已执行的原请求，重新登录同一账户后原样重试。旧席位 token 的 scope 不变。

房间密码设置的请求指纹对账户使用服务端稳定的用户/战役派生密钥，不能用短期会话 token；原 Unity 凭证继续使用原指纹算法。退出/换账户后，旧请求的迟到 401 不得登出新账户；页面加载遭遇当前会话失效应保留可用登录表单。

创建战役没有请求回执；响应未知时不自动重建，先刷新账户战役列表。完整备份必须包含整个数据目录，特别是 `accounts.json` 的账户、会话及指纹密钥；只复制战役文件不能保留账户访问和请求恢复关系。

## 错误与边界

- 401 `account_unauthorized`：用户名/密码或会话无效；禁用、撤销和到期均拒绝。
- 403 `forbidden`：非管理员管理账户、普通用户访问他人战役。
- 403 `admin_protected`：尝试停用或通过他人重置入口修改唯一管理员。
- 409 `account_exists`：用户名重复；409 `invalid_account_store`：账户存储损坏或不支持。
- 429 `account_login_rate_limited`：登录尝试过密，按响应 `Retry-After` 等待。

原席位能力接口仍用于 Unity/旧客户端兼容；账户功能没有把整个服务改成公网产品。远程工作台仍要求 HTTPS，没有开放 CORS；默认监听仍为 loopback。本次不修改正式存档或自动切换运行中的服务。

## 验证依据

`tests/DiceRealm.Tests/AccountTests.cs` 覆盖登录/撤销/禁用/改密、跨用户权限、重启、创建归属、旧 JSON 与 SQLite 列表、Unity 凭证、稳定房间指纹、坏记录和限流。`client-workbench/tests/accounts.test.js` 覆盖传输/投影、密码不落浏览器存储、稳定 pending scope、列表与视图销毁、迟到错误身份。

真实浏览器证据位于 `artifacts/workbench-user-accounts/`：隔离数据中从登录到创建、切换、管理员操作、重启及 100%/150% 页面检查；另在真实已提交房间设置丢失响应后，退出/重登并原字节重试，确认返回 replayed 且版本不重复推进。不使用正式战役或真实模型调用。账户菜单与坏条目隔离的修订验收在 `artifacts/account-navigation/browser-verification.json`：包内实际账户登录、菜单键盘/焦点、好坏混合列表、普通用户隔离和100%/150%桌面截图；坏文件字节不变，测试服务已停止。
