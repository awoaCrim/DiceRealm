# DM剧本库

新房间的「剧本与提示词」页先显示剧本库。点击某部剧本的启用按钮，一次采用该包的剧本、原样叙事提示词和随附原图；没有第二次确认，也不调用文字或图片模型。手动导入仍可用。空房不会自动选择故事，已有队员与审核状态保留。

已开始的房间只能浏览剧本库，不能替换或重置当前剧情。体验另一部剧本，请在「我的战役」新建房间。启用后的剧本固定，后续提示词仍使用既有编辑/发布流程。

基础运行包含原创《雨桥失信》；《雾港灯塔》已按用户要求移除，不再随新运行包提供。
- 《雨桥失信》：雨中寻人、踪迹调查与护送，建议1级，约1次短游戏，不强制战斗。

用户指定的第三方冒险可以作为本机包安装，同样出现在剧本库。来源说明必须区分原文、整理摘要、原创扩展和已实现机械范围；网站有完整剧本不等于此程序已经自动实现全部规则。商业原文和地图不随公共基础程序再分发。LMoP本机包的具体覆盖与验证保留在本次任务资料中。

启用后在「剧本与提示词 → 地图图册」只读查看随包地图。选择图片才通过原鉴权接口读取像素；可适应宽度或查看原始尺寸，主持版与已发布玩家版明确区分。刷新、切页和换战役不会生成、发布或修改地图。玩家端仍只显示已发布玩家图。

本次本机《凡戴尔失落矿坑》整理包覆盖四章、21个宏观地点与31条当前场景私有主持摘要，含7组玩家/主持原图。它不是完整译本或逐室战术自动化；未实现的2014怪物、机关、奖励与成长仍走现有裁定，不静默替换成2024数据。阿加莎、老枭井、飞龙山丘不绑定地区大图，保留缺图按需生成；新增地图借用公开原图的外观描述并标注扩展。图片服务未配置时不会假装可以出图。

剧本库只显示简介、适用等级、时长、地点/地图数量和可用的启用按钮，不展示版本、来源按钮或外部工具区。包的来源与许可仍保留在后台元数据。

契约55的agent直接使用内置2024工具：`dm_reference`查检定、物件、陷阱、危险和CR指引；`encounter_plan`按实际队伍等级计算预算、选怪或评估混合名单；`treasure_generate`生成个人/宝库战利品方案。无需使用者打开外部网页。来源仍按固定pin核验，不套用2014的遭遇倍率、任意怪物CR反算或战利品表；资料/规划可用不等于支持自动结算。详情见[主持辅助工具](harness-runtime.md#主持辅助工具契约55)。

## 本机包

默认读取服务端程序目录下的`adventures/<id>/`，基础内容来自`content/adventures/`并随构建复制。需要指定独立私有库时，可设置服务端`AdventureLibrary:Directory`；它指向完整库目录，不下载远程内容。

每包三个必需文件：
- `package.json`：`formatVersion:1`、`id`、`name`、`version`、`summary`、`levels`、`duration`、`source`、`license`、`maps`。
- `adventure.json`：现有`AdventureDocument`，经过同一个`ContentValidator`，不是另一种剧情引擎。
- `prompt.md`：UTF-8原样提示词，经过同一个`HarnessProfiles`校验。

`name/version`须与剧本一致。ID为小写字母数字和短横线；地图文件仅允许包内简单PNG文件名，不接受路径或URL下载。地图项为`{file,sha256,specification,sceneIds}`，规格必须带`importSource`；尺寸与PNG实测一致，场景ID属于该剧本。`maps:[]`为合法无原图包，未来仍可按需生成。

库指纹绑定manifest、剧本和提示词原字节；manifest再绑定每张PNG的SHA-256。激活前校验全部PNG、大小、结构和引用，缺失/坏文件拒绝，不把有问题的包当作空白故事。玩家原图在启用时公开，主持原图始终私有。公开的是整张玩家图，没有探索迷雾，来源和视觉描述应可公开；未核比例尺保持`uncalibrated`。

## HTTP、回执与恢复

主持鉴权后：
- `GET /api/v1/campaigns/{id}/content/library`返回`{adventures,canActivate,notice}`，仅摘要/版本/来源/数量/指纹，不读取地图像素、不修改游戏或自动启用。
- `POST /api/v1/campaigns/{id}/content/library/activate`提交`{requestId,expectedVersion,libraryId,hash}`，返回标准`ActionResponse`，`resolution.kind=content.library`。不是由浏览器上传或拼接剧本文本。

复用原`ChangeContent`：授权、主持门禁、原回执、版本、归档，再执行首次设定。已完成同请求先回执，不因库文件移动、当前版本变化或重启再次安装；同请求不同内容冲突。首次设置验证、场景、种子知识与游戏事件/回执仍由原游戏事务拥有。

地图有独立文件生命周期。整包文件先检查，在游戏gate内初始化候选内容并沿`MapCatalog.Create → Import → ConfigureScenes → Publish`装入；全部导入/关联完成后才发布玩家图，最后提交游戏状态。每阶段ID按战役、包指纹、文件和阶段确定，固定使用原阶段版本1/2/3，不使用重放返回的最新版本重新构造请求。失败不报告全部启用；地图阶段可能已持久化，重试原请求继续已有回执，不删除或重生图。这不是跨SQLite与所有PNG文件的全局事务，也不会自动清除失败后留存的原图。

工作台沿现有`ctx.submit`和pending记录恢复，点击后冻结包指纹与房间版本，双击只提交一次；离页、换账户、旧响应与新版本不能继续旧按钮。已确认但刷新失败不重新启用。已启用房间显示新建指引，不加“强制替换”入口。

验证入口：`AdventureLibraryTests`、`ImportedMapTests`、工作台`adventure-library.test.js`；自动图和首次设定原回归保持。真实Pi/MCP配fake图片验证按需扩展风格选择；不把fake像素当作真实地图质量。
