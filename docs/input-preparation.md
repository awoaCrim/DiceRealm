# 输入式开局与内容准备

主持人在工作台「剧情与地图 › 内容准备与启用」的「输入式准备」页签提供自己的原文、设定和冒险意图，系统整理成有来源的提议，指出缺口；整体检查后采用为剧本草稿，隔离试跑，再明确导入并启用。高级表单保留为纠错工具，不要求逐个建立场景、人物、目标或线索。

系统没有默认故事、默认整理提示词或默认游玩提示词。本功能提供受限的准备流程，不代表自由文本已经能够自动生成完整 D&D 规则、战斗、奖励或地图。

## 使用步骤

1. 创建房间（只需房间名）或连接自己的主持席位。在内容准备页保存自己的私有连接文件，便于关页后重新连接。
2. 粘贴原文与意图，或选择 UTF-8 TXT / Markdown；文件上限 1 MiB、文本上限 200000 字符。未编辑的文件保留 BOM 和 CR/LF。填写冒险名称、文档标识与版本。
3. 明确选择规则选项：所有已声明路线共用的旅行秒数可留空；有路线但留空时先澄清，不默认使用 600 秒。0 表示明确不推进旅行时间。「起点允许安全休息与邀请队员」默认不勾选，由主持明确设置。
4. 在折叠区域提供自己的内容整理提示词标识、版本和原文。它独立于游玩的 Intent/Narration 提示词，不会自动复制或改写它们。
5. 点击「整理为冒险草稿」，阅读模型、资料外发与可能计费说明后确认。只有这一步会请求配置的文本供应商；普通编辑、读取、检查、采用、导入、启用均不调用准备供应商。
6. 查看场景、起点、路线及人物/任务/地点/线索的依据和公开范围。每条提议的摘录已逐字核对，但**摘录匹配不能证明模型解释忠实**。缺失地点、起点、旅行时间或模型提出的问题会显示为待澄清，不产生可采用的完整文档。可修改资料后重新整理；仅调整规则选项时，也可对已有提议重新检查，无需再次外发。
7. 明确「采用为剧本草稿」，进入「检查、导入与试跑」。采用只替换本浏览器草稿；再提供自己的游玩提示词、检查引用、创建离线试跑，最后分别确认导入和启用。已经启用的战役不能替换剧本，新冒险应新建战役。
8. 导出自己的连接文件，在 Unity「设置 › 连接」填写相同服务地址及本机文件路径，明确导入连接。文件含席位凭证，不能作为剧本分享。

本页离线试跑的自由行动沿用旧 `/actions` 接口，只测试待裁定；结构化按钮由真实服务端执行。Unity 的新主输入走 `/actions/input`。两者都受服务端永久 `OfflineTrial` 标记保护，不调用文本或图片供应商；离线结果不能证明真实模型语言质量。

## 支持的整理范围

输出合同见 [preparation-proposal.schema.json](../schemas/preparation-proposal.schema.json)，服务端最终边界见 [PreparationModels](../server/DiceRealm.Server/Domain/PreparationModels.cs)。

- 最多 40 个场景、80 条有向路线、64 条非机械知识、20 个问题。没有可确认的场景或起点时先澄清，不默取第一个地点。
- 每个场景、路线和知识条目包含 1–8 个来源摘录。`field` 只能是 `sourceText` 或 `intent`；`start/length` 使用从零开始的 UTF-16 code unit，`quote` 必须等于对应范围，单条最多 2000 字符。
- 只接受 `npc / quest / place / clue` 知识。名称、摘要、状态记录不会发放奖励、制造任务完成条件、增加规则事实、移动角色或扣除资源。
- 知识的 `visibility` 为 `public`、`host` 或 `arrival`。`arrival` 必须指定合法的 `revealSceneId`，实际访问后才向玩家公开；`host` 永不向普通席位公开。未知所在地用空 `sceneId`，不猜位置。
- 模型不能返回 DC、骰点、HP、物品、奖励、资源、facts、坐标、条件或 effects。额外字段、重复字段、错大小写、缺失必需字段、未知引用、错误摘录或超限会拒绝整份提议，不保留半份绑定。
- 提议投影后还必须通过原有 `ContentValidator`。复杂规则、门锁条件、奖励或遭遇仍需明确的高级内容或主持裁定，不能仅凭叙事产生执行效果。

生成场景全部带 `unlocated:true`，即使旧 DTO 仍有 `x/y`，消费者也不得把它们当作位置证据。Unity 在当前可见节点中存在未知位置时使用文字地点列表，不绘制坐标或路线；选择合法地点仍进入原有旅行预览和确认。全部已定位的旧内容保留原地图显示。

非机械内容写入可选 `AdventureDocument.initialKnowledge`，启用时进入世界信息投影，不硬塞入空完成条件恒真的规则任务。旧文档不含此字段、旧场景不含 `unlocated` 时保持原序列化指纹与回执。准备提示词不扩展旧 `PromptBundle` 的形状。

## 草稿、冲突与恢复

准备资料、已采用剧本草稿、游玩提示词草稿、准备回执及未确认准备请求保存在本浏览器 IndexedDB。scope 包含服务 origin、战役和席位摘要；它不是加密，同源脚本和能访问浏览器资料的人仍可能读到私人内容。凭证本身仍只在当前标签页 sessionStorage 和明确导出的连接文件中，不写进准备库。

关页后用原连接重新进入同一浏览器，可恢复草稿；不提供跨设备同步，也不保证浏览器清理数据后还能恢复。建议使用「下载完整准备备份」。备份只能明确恢复到原 scope，不能覆盖另一份未确认准备请求；损坏记录保留并提供原始下载，不能当空白覆盖。旧 sessionStorage 草稿只在新库为空时迁入，并保留旧原始记录作为恢复副本。

不同标签页通过 IndexedDB 事务 CAS 比较修订。冲突时保留本页输入、禁覆盖，提供下载及明确载入已保存草稿；通知只帮助发现冲突，不承担正确性。导入/试跑的确认前还会核对持久修订，即使通知丢失也拒绝过期草稿。异步文件读取、检查和确认不能替换后来输入或对已经离开的页面发命令。

输入修订与准备操作修订分开：较旧检查、生成、确认或采用不能覆盖后来操作；结果到达只保存回执，不自动采用。已经可能发送的请求保留原 UUID 和完整正文；点击「确认原整理请求」重放同一请求，不更新原资料、不重新分配 ID。响应丢失后即使关页，也能从同一 scope 恢复。

`unknown` 表示服务端在可能外发前已保存操作，但没有可靠的完成结果。重启或原样重试不再次外发；不能承诺供应商从未收到请求或恰好计费一次。准备失败不会更换正式绑定、推进版本或清除较新输入。

普通导入、绑定、启用、试跑行动仍使用原 sessionStorage pending 机制，不具有准备请求的关页持久承诺；存在此类未确认操作时应先重试确认再关闭标签页。

## 服务端协议与配置

主持 Bearer 权限；前缀 `/api/v1/campaigns/{id}/content/preparation`。记录不推进战役版本，不占用游戏行动 pending，不替代正式导入。

| 路径 | 输入 / 返回 |
|---|---|
| `GET /status` | `{enabled, model, maximumSourceCharacters, maximumInputBytes, notice}`；无模型、离线试跑或归档时禁新整理 |
| `POST` 根路径 | `{requestId, input, prompt, confirmProviderUse:true}` → `PreparationResult` |
| `GET /requests/{requestId}` | 读取已有回执，不调用供应商；不存在为 404 |
| `POST /inspect` | `{input, proposal}` → `{status,inputHash,proposal,document,issues}`；纯校验与投影，无外发 |

`input` 字段：`sourceText`、`intent`、`name`、`adventureId`、`adventureVersion`、`startSafeRest`、`travelSeconds`。`prompt` 字段：`id`、`version`、`text`。意图最多 8000 字符，准备提示词最多 32768 字符。单次 API 正文上限 1 MiB；完整外发 HTTP JSON（含提示词、模型字段和转义）另受 128 KiB 上限，不能以原文字符数估算一定可外发。供应商响应上限 256 KiB。

`PreparationResult` 包含 `requestId,status,inputHash,promptHash,proposal,document,issues,providerModel`。状态为 `ready / needs_clarification / failed / unknown`，只有 `ready` 才有可采用文档。失败响应不回显供应商私密正文。身份、形状、同意和业务拒绝使用 4xx；已开始操作的生成错误保存为终态 `failed`。

| 情况 | 结果 |
|---|---|
| 无凭证 / 其他战役凭证 / 非主持 | 401 / 401 / 403，不读准备资料、不外发 |
| 缺少明确外发同意 | `provider_consent_required` |
| 输入或提示词不合法 | `invalid_preparation` |
| 同 ID 不同内容 | 409 `preparation_conflict` |
| 新请求无配置 / 离线试跑 / 已归档 | `preparation_disabled` / `preparation_disabled` / `campaign_archived` |
| 每战役累计 128 个准备操作 | `preparation_capacity`；不删除旧回执，可继续本地编辑、检查或在新战役准备 |
| 供应商超时、无效输出、额度耗尽 | 保存 `failed`，没有半份正式内容；旧 ID 不再次调用 |

准备供应商沿用服务端 `TextAi:Endpoint/ApiKey/Model`，缺少 key 或 model 时不选择默认模型。系统消息仅包含主持提供的准备提示词原文；受限机器输出合同放在 user 数据内。这里只外发本次明确提交的 source/intent，不读取其他战役内容；普通玩家理解/叙事仍使用有界公开上下文，不能借准备功能恢复发送完整 sourceText、facts、主持秘密或未到达知识。

`PreparationAi:TimeoutSeconds` 默认 120，限制 5–300；`PreparationAi:MaximumTokens` 默认 4096，限制 256–16384。浏览器现有请求超时为 60 秒，超时后保持原请求恢复，不自动追加调用。环境变量写法见 [.env.example](../.env.example)。

服务端 `data/preparation/{campaignId}.json` 独立原子保存回执，单数据目录仍只允许一个服务写入。同战役准备调用串行，同 ID 并发只外发一次；供应商等待不长期持有 CampaignStore 游戏锁。记录损坏或未知 schema 拒绝并保留原文件，不初始化空记录覆盖。调用前持久保存 unknown，再预留文本尝试额度；失败与超时仍计尝试，额度不是金额上限。

## 真实模型评估

自动化和浏览器/原生 Player 使用明确的本地 QA 文本与模拟供应商，不内置生产内容，不代表真实模型理解或叙事质量。

真实供应商评估需要明确三项授权：**准确的模型与供应商、允许外发的测试原文和提示词、金额上限及最大尝试次数**。建议一次小规模试验只用一份不含私人资料的短文、一次整理、一次明确修订及约 10 次连续玩家输入；上限由用户决定，不自行使用建议额度。

评估需保留每次输入、来源摘录、待澄清问题、版本、耗时、提供方用量/费用及语义人工核对。检查无依据场景/路线、错误公开、遗漏关键资料、奖励或检定幻觉，以及连续游玩的目标承接。先通过来源和隐私检查，再考虑扩大样本；出现外发错误、费用接近上限或无法可靠核对时立即停止，不自动重试。供应商质量评估与正式服务部署分别授权。
