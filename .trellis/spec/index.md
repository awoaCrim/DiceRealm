# DiceRealm 开发规范

这是后续开发的决策依据，不是当前代码的逐行说明。优先让规则易理解、易验证、易修改；旧代码不一致时，保护既有契约，在本次改动范围内逐步改善，不顺手重写整个项目。

所有设计、实现与审查须遵守项目根 AGENTS.md 的“禁止过度编程与过度防御”铁律。新增复杂性必须有当前需求依据，不得恢复用户已要求移除的解锁、重复确认或额度门槛。

## 先读哪些文件

1. 当前任务的需求与验收；复杂任务再读设计和执行计划。
2. [共享设计指引](guides/index.md)，按改动选择具体指引。
3. [后端](backend/index.md) 或 [前端](frontend/index.md) 的 Pre-Development Checklist。
4. 改协议、状态、重试或权限时读 [跨端契约](contracts.md)；选择验证范围时读 [验证规范](verification.md)。

## 文档职责

产品现状与下一步见 [当前状态](../../docs/current-status.md)，功能/协议/历史证据见 [文档索引](../../docs/README.md)。Harness 运行与工作区的详细协议分别在 [运行](../../docs/harness-runtime.md)、[工作区](../../docs/harness-workspace.md) 维护。

- 本目录：今后应遵守的规则、理由、边界和代表性例子。标为「现状」的内容不代表推荐复制；标为「新代码要求」的内容不宣称旧代码已全部符合。
- `docs/`：具体功能协议、使用方法、规则覆盖和历史验收证据。详细字段只维护在对应协议中，这里链接过去。
- 任务目录：本次范围、权衡、临时证据和未完成项，不把一次性的 PID、端口占用或测试计数写成长期规范。
- AGENTS.md：用户授权与项目约定；协作入口：当前任务与验收。不要在各层复制审批流程。

## 公开仓库

GitHub `awoaCrim/DiceRealm` 只接收 `scripts/publish-github.py` 从本地已提交内容导出的公开部分：服务端、测试、两个网页、agent-host、内容、schemas、`docs/` 与本目录。本地 `main` 含研究记录、会话日志和 Unity 工程，不直接推送。导出在远端 `main` 上追加提交，不强推；每次推送仍需用户要求（2026-11-22 用户首次要求上传，原仓库旧内容不再保留在当前树中）。

## 技术与产品边界

当前为 .NET 10 权威服务端、Unity 6 UI Toolkit / uGUI 玩家端和原生 JavaScript ES modules 主持工作台。2026-11-21 用户确认玩家端改为浏览器打开的网页，逐步替代 Unity；网页覆盖完整游玩流程并经用户实玩确认前，Unity 仍是现行玩家端。版本以 [global.json](../../global.json)、Unity 版本 和各工程清单为准。Git 提交规则见 AGENTS.md。

- 服务端决定骰点、资源、角色和世界变化；两个前端只提交意图并展示结果。
- 冒险剧本和探索提示词由使用者导入，或明确从剧本库选择启用；空房不自动套用故事。战斗主持按用户要求内置一套默认稿，自定义稿优先，已开始的战斗保留冻结原文，见[外部集成与规则边界](backend/integrations.md#内置战斗主持提示词契约54)。
- 可创建某职业或查到某条规则，不等于已支持自动结算；未覆盖行为明确进入裁定。
- 玩家围绕「处境 → 输入行动 → 回应 → 下一步」，冒险操作尽量直接输入。服务器/LLM承担日常叙事、冒险推进及地点、人物、任务、线索与地图标记维护；人工DM主要审核批准角色、处理部分LLM无法可靠决定的问题，并在LLM出错时纠正，不承担日常主持、逐条审批或逐项录入。按钮、表单与对象编辑只作可选辅助，不能成为正常游玩的前置流程。具体要求见 [使用者流程](frontend/user-experience.md)，当前缺失能力不得伪称已实现。
- 不为遵守规范引入无现实收益的框架、依赖、接口、配置开关或全库格式化。

规范用中文解释，代码符号和协议名保留原样。重要规则给出源码、测试或设计理由；示例仅证明对应边界，不要求复制文件中的全部写法。
