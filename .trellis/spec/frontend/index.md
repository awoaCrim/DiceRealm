# 双前端规范

Unity 面向既有玩家游玩，浏览器工作台面向 PC 桌面主持、内容准备，以及已有真实玩家席位的本人行动；新建战役仅产生无角色主持，不在网页建卡；不要求 H5／手机适配。工作台呈现战役、内容、行动、回答、本人确认与结果；主持在剧情页可在对应DM消息下查看该轮安全的模型/工具步骤，不在顶部汇总，成功后保留并默认折叠，可按需读取历史步骤与本轮保留的请求详情。仍不提供 Run/hash 管理或执行引擎选择；执行内核留在服务端。两者都是权威 API 的消费者，不共用 UI 框架、不各建一套规则引擎。

## Pre-Development Checklist

- 2026-11-21 用户确认：玩家端改为浏览器打开的网页（不需要桌面程序），逐步替代 Unity。迁移顺序与现状见 V3 实现计划。
- 先读 [使用者流程](user-experience.md)，确定用户要完成的行为和主次信息。
- 2026-11-07 起前端按 [视觉规范 V3「墨卷」](visual-v3.md) 重写（Unity 纯 UI Toolkit + 工作台重写）；已迁移页面以 V3 为准，未迁移页面暂按下条 v2。工作台已整页迁移（外壳、登录、剧情页按 A3 稿，其余页面用 V3 令牌与通用组件），工作台样式不再参照 v2 / workbench-style.md。
- 任何视觉/布局/组件外观改动先读 [前端视觉规范 v2](visual-v2.md)（游戏端 G2 + BG3；2026-11-05 用户将工作台剧情首页改为 G2 背景地图与透明浮窗，管理页保留 W-C）；它覆盖 unity.md 与 workbench-style.md 中的旧配色和组件外观。
- Unity 改动读 [Unity 分层与生命周期](unity.md)（含桌面密度/字体采样、叙事、骰子、战斗与地图演出、聊天全文与轮数设置/无右侧动态栏/角色状态与来源按需阅读、三页签日志与世界分类读取、新旧战役发现、业务确认分离与本机恢复）；工作台改动读 [浏览器分层与生命周期](workbench.md)，涉及样式/配色/组件外观读 [工作台视觉规范](workbench-style.md)（深色金色主持台）；剧情侧栏另见 [主持概览接口](../../../docs/workbench-dm-overview.md)，遵循上述规范的权限、只读与同步边界。
- 建卡、草稿、角色归档和入房改动读 [全屏建卡与本机角色](character-creation.md)。头像与图片读取改动另读 [角色头像](../../../docs/character-portraits.md)，保留同版本刷新、会话权限和显式进入补登记边界。
- 提交、预览、DTO、历史、会话或权限改变时读 [跨端契约](../contracts.md)；工作台账户、用户切换和登录恢复同时读 [账户规范](../backend/accounts.md)。
- 确定成功、空白、等待、失败、只读/无权限、旧记录六种状态中哪些受影响。
- 按 [验证规范](../verification.md) 选测试，不把浏览器设计稿当 Unity 实际效果。

## Quality Check

- 页面围绕操作组织，内部字段/原始 JSON/规则明细只在需要时出现。
- 显示结果有服务端依据，不拼接另一条行动的回应，不猜 DC、费用或成功状态。
- 未发送草稿、已发送但未确认请求、权威快照分别管理，保存期限表达准确。
- 异步返回校验会话/视图代次；退出、换场景、关闭窗口后不被旧请求更新。
- 没有跨席位草稿/缓存泄漏；隐藏控件不是权限边界。
- 修改交互时检查输入焦点、键盘、长文、缩放与桌面窗口；工作台不增加手机视口/触屏验收；同步不抢阅读位置。
- 按实际运行层报告验证，不以 Core/DOM 替身通过声称原生输入或布局已通过。
