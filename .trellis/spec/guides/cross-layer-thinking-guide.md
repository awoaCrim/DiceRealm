# 跨层检查

适用于新增字段、命令、事件、来源规则、存储格式或任何一端行为的改变。

## 先追一条真实链路

```text
使用者选择/输入 → 客户端请求保存 → HTTP 校验与授权
→ 应用协调 → Domain 判定 → 原子保存 → 席位投影 → 解码 → UI
```

- 谁拥有真相？是否把应由服务端决定的资源或成功状态放到了 UI？
- 哪些输入不可信？请求、导入文档、模型输出和存档版本分别在哪个边界验证？
- 这是查询、纯预览、权威命令还是外部付费调用？取消、失败、重试的后果是否不同？
- 响应丢失但已经保存时会怎样？换战役、换席位、页面销毁后晚到的响应会怎样？
- 新字段的缺失、null、空数组、零和旧版本各是什么意思？Unity 的实际反序列化是否一致？
- 普通玩家、主持、其他战役和已撤销席位分别能看到或操作什么？
- 历史分页和关联结果是否属于同一个行动、同一读取范围？
- 更新了服务端投影后，是否同步检查 Unity DTO/归一化、工作台校验、契约文档和相关测试？

具体行为见 [跨端契约](../contracts.md)、[持久化](../backend/database-guidelines.md)、[Unity](../frontend/unity.md) 和 [工作台](../frontend/workbench.md)。不要在任务中重复建立一份字段规格；记录变更点并链接到唯一维护位置。
