# DiceRealm 主持工作台

DM 用的浏览器后台：看剧情、处理需要人工判断的事、查看模型请求、配置 AI、剧本与提示词。面向 PC 桌面键鼠，不开发或验收 H5／手机适配。视觉为 V3「墨卷」：亮色纸面、细墨线、朱砂批注，思源宋体/黑体只用 400 字重；配色令牌与剧情页规则见 [视觉规范 V3](../.trellis/spec/frontend/visual-v3.md)，设计稿 `artifacts/ui-design-iteration/v3/a3-ink/workbench.html`。

创建战役只填名称；创建后在「剧本」导入自己的剧本 JSON 与叙事提示词并启用，不附带默认故事。玩家在 `/play/` 用房间号与共享密码完整建卡后加入（Unity 仍可用），主持在剧情页审核；房间流程见[房间协议](../docs/room-onboarding.md)。

玩家端正在迁到同一目录下的浏览器页面 `/play/`（`play.html`、`src/play/`、`styles/play.css`），复用这里的 API、剧情流和样式令牌；已完成主冒险页、入口（本机席位、加入房间）、快速建卡（选职业、起名字即加入）与八步完整建卡、角色窗（复用 `character-sheet.js` 并加本人操作与升级）、冒险手记（复用世界记录）与战斗（先攻名单、回合预算与行动按钮、战斗底图上的格位、「需要你回应」卡、在地图上选区域法术中心与分配魔法飞弹），以及左栏悬停角色卡、M 键大图和探索地图上的公开图钉（悬停看资料，可前往的地点点击后进入原行动确认卡，画外地点在边缘指示）。进度见 V3 实现计划，实机走查见 实机验收。

### 运行

工作台由 ASP.NET Core 服务端同源托管，静态文件嵌入构建产物，不需要启动 Node 服务或安装前端依赖。从仓库根目录启动：

```bash
dotnet run --project server/DiceRealm.Server
```

打开 `http://127.0.0.1:5180/workbench/`，使用账户登录。首次初始化内置 `admin`，密码为用户指定初始值；普通账户由管理员创建。修改源文件后需重新构建、重启服务端。默认服务仅用于本机，不应直接暴露公网。

### 页面

顶栏：朱砂小印与战役名、房间号（主持，可复制）、连接状态与在场玩家数、我的战役、账户菜单（用户管理/修改密码/退出），另有阅读设置。左侧目录按工作类型分为「壹 本场」「贰 战役」「叁 内容」「肆 管理」，不按权限：本场是这一场正在发生的事，战役是席位与存档的维护，内容是开团前准备的素材，管理是账户级设置（仅 admin）。当前席位看不到某一组的全部页面时，整组不显示；剧情项旁的数字是主持待办数。

| 分组 | 页面 | 内容 |
|---|---|---|
| 本场 | 剧情（默认） | 三栏：导航 \| 剧情 \| 右侧停靠栏。剧情用小说/剧本体：同一字号同一左边线，对话写「着色人名：正文」，旁白浅一级，“仅 X 可见”是段首小标签加赭色正文，检定一行连读并紧跟结果小方印，时间在右侧且同一分钟只显示一次；初次加载到底部，可读更早记录。剧情顶部的「主持事项」停靠条只在有真实待办时出现，每条一行；选中后右栏从「主持概览」（队伍、当前场景私密资料、只读 DM 小地图与完整地图窗）切换为该事项的处理窗，非模态、不遮剧情，关闭恢复原选择；概览可收起。角色资料从人名、概览队伍或“队伍成员”打开，未发言角色也可查看，能力按取得来源分组并读取同源完整规则；每条 DM 消息下的「本轮步骤」仅主持可见，成功轮次默认折叠，参数/返回及 HTTP 请求在独立宽窗口阅读（见[接口说明](../docs/workbench-dm-overview.md)） |
| 本场 | 世界记录 | 当前地点、剧本任务进度、剧本人物与阵营，以及另列的冒险记录；检索仅覆盖当前类别冒险记录，不含剧本概览 |
| 战役 | 邀请玩家（主持） | 查看房间号与加入状态，设置或更换共享密码、关闭新加入；已有玩家进入后仍可继续邀请，不影响已有席位 |
| 战役 | 存档与重开（主持） | 命名保存、读取、覆盖、删除与重开整场游戏；读档与重开前自动保留恢复点，保持房间与当前合法席位。不回退账户与已发生的供应商费用 |
| 内容 | 剧本（主持） | 首次设定导入并启用；之后按目录阅读场景、路线、行动、遭遇、任务、人物与开局知识，保留剧本库与来源 |
| 内容 | 地图图册（主持） | 按需阅读主持图/玩家图及发布状态；无选图不下载，不自动生成或发布 |
| 内容 | 提示词（主持） | 可分别编辑探索与战斗主持；战斗内置默认稿，自定义优先，清空并保存恢复默认。左侧选择 System 段落或按需工作方法，右侧编辑当前内容，顶部保存与版本状态固定；保留全文、文件导入、生效原文。「注入位置」说明动态消息/状态/工具来源，「已发送请求」读取真实日志。草稿同标签页切页/刷新保留，保存即生效 |
| 管理 | 请求日志（admin） | 每次模型请求的来源、行动、尝试次数、耗时与结果；宽窗口左侧选择已加载记录，右侧切换响应／请求／概况；请求分段正文直接显示，原文通过具名按钮查看，保留复制、失败筛选及分页 |
| 管理 | AI 设置（admin） | 叙事主模型与辅助模型的接口、模型名称和密钥 |

剧情页的执行过程展开为分类时间线，显示规则查询、已记录检定、世界写入与被拒绝后重试的摘要；点击仍进入参数/返回详情。成功/失败检定以青瓷/暗红小方印标出。新消息、面板入场与数值变化采用短动效，点击/按键可跳过；“阅读设置”的动画开关和系统减少动画设置均生效，初次加载、历史与重连补读保持静态。

战斗时，剧情上方的战况条可打开「战况／战报」窗口，查看先攻、当前行动者、单位生命与行动预算、格位和队员等待；已结算战斗短报无需等AI叙事。单位与战报详情按需阅读，不提供代投或移动操作。用法及只读接口见[工作台战斗信息](../docs/workbench-combat.md)。

队员只有剧情与世界记录。服务端对每次写入重新检查席位与版本，导航隐藏不代替鉴权。

### 凭证与未确认请求

账户会话和未确认的管理写入保存在当前标签页的 `sessionStorage`，不写入 URL、日志或 `localStorage`。写入发送前保存原请求；响应丢失、超时或服务端暂时失败时阻止其他写入，并提供原请求重试。未提交的裁定、剧情后果与更正草稿在当前标签页内存中保留。提示词草稿按账户/战役隔离保存在同标签页 sessionStorage；确认保存或明确放弃后清理，服务端版本变化先保留草稿并提示处理。关闭标签页会清除登录状态且不保证保留上述草稿；字号与减少动画偏好单独保存在 `localStorage`。

### 测试

在本目录执行：

```bash
npm test
```

使用 Node 内置测试运行器，无需第三方库。[工作台页面测试](tests/dm-workbench.test.js) 覆盖请求体分段、提示词分段往返、剧情线消息与分页、提示词保存顺序和请求日志；[协议测试](tests/client.test.js) 覆盖来源与身份校验、席位隔离和原请求重试；[内容导入测试](tests/content.test.js) 覆盖剧本解析与非法文档。
